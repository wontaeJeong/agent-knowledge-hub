## Security boundary and review context

- Runtime-issued exact-operation grant for the authenticated human/browser session only. Existing machine/delegated credentials, agents and schedules cannot submit bulk. Global credential action ceiling remains read-only `knowledge.read`; no general machine write scope was added.
- Frozen request hash binds reason and ordered target/ordinal/patch/baseline/source/ancestor identifiers. Grant binds payload hash/key/job and original parent session. Token secret is stored only as a hash; no reusable bearer is persisted by bulk.
- Grant expires at the earlier runtime timeout (default120s, configurable up to1h) or original session expiry. Parent session/current external identity and active human account are revalidated. Worker restart never refreshes or extends consent; expired/revoked jobs fail visibly and require a current preview/explicit new consent.
- Temporary credential-less same-human Context exists only inside trusted executeBulk. Its authorization asserts the lease identity; every domain-commit transaction checks current original grant/session/actor/job/hash, frozen rows, lease fence, erasure, canonical action, target/source and complete current/destination parent lineage. It is never returned or reused by another endpoint.
- Move/archive call the existing canonical state writer within the effect transaction. Proposal and per-item needs-review receipt commit together via existing publication callbacks. Worker receipt/effect fence prevents duplicate effects after actual SIGKILL and restart. Known stale/denied/policy errors are explicit item states; unknown errors stop/fail the job rather than fabricate successful items.
- Preview expiry alone cannot extend consent. Failed admission with only mutation marked still expires. A post-expiry replay requires the actual persisted same actor/key/hash job; its original grant must exist. Response-loss after enqueue but before request.job_id persistence is recovered by exact job lookup. Different actor/mutation/input hash/session is denied. Original session termination denies reads/replay. Individual resource revocation does not block other authorized items: the revoked item executes denied, its result/ID/title/count is omitted, and remaining items proceed.
- General jobs APIs expose only original-session queue status for bulk, with result and checkpoint null. Per-item reads are projected twice around identity refresh with current read/source/ancestor checks and original-session binding. No hidden total/count is supplied. UI removes omitted/unavailable cached names, candidates, selections and previews, preserves authorized selections, uses a generic count-free removal notice, and rejects late responses after identity/space/input epoch changes.
- Bulk request/item records join explicit retention inventory and source/page lineage. Erasure follows item→request→job, redacts payload/receipt and cancels the job; no new plan appears after the erasure fence. Closed queue lane enum is preserved and idempotency text is uniquely scrubbed. Existing hold/retention regressions are retained; no production privacy acceptance claim.

# Persistent content boundary

The host supplies an authenticated, selected-space `Context`, `Pool`, canonical app-owned PVC path, and **mandatory** transaction authorizer. No module starts or mounts an unauthenticated server. See `routes.ts` for the exact pure extension contract.

```ts
const service = new StorageService(
  pool,
  new FileBlobStore(blobRoot),
  authorizer,
);
const route = storageRoutes(
  service,
  new UrlCollector({
    enabled: false,
    approvedOrigins: [],
  }),
);
```

`blobRoot` is an explicit constructor configuration; the host may map `AKH_BLOB_ROOT` to it. No default temporary store exists. Mount a persistent filesystem there and keep it inaccessible to untrusted writers. Metadata in migration 021 and CAS files must be backed up/restored together. Keep all hashes referenced by `storage_blobs` **and** `storage_imports.manifest.stagedBlobs`; failed writes can leave unreferenced CAS objects, which are safe but require coordinated retention/GC, not eager deletion.

## HTTP hook

Pass `{method,path,body,ctx,send,req,res}` to the returned `handleStorageRoute`. `path` includes `/api/v1/storage/`. The host must perform authentication/session validation, CSRF, allowed-origin and selected-space resolution **before** calling it. For raw PUT, call before reading/parsing the body. Other JSON endpoints need a bounded host body parser (5 MiB maximum). Errors propagate to the host's safe error mapper. Never serialize native error paths or stack traces.

## Security and actual caps

- Raw upload/download: 5 MiB per file, incrementally read and elapsed-time bounded (30 seconds), then at most 5 MiB buffered to validate and recheck ACL before commit/return. This is not an unlimited zero-copy streaming system.
- Import/export: **total JSON 5 MiB**, at most 100 pages/sources/blobs, at most 100 versions per imported page. Export fails rather than silently truncating ancestry or unscanned attachments.
- UTF8 text/Markdown/JSON: reject invalid encoding, control/binary camouflage and HTML markup. Exact extensions/MIME enforced. PDF signature/end marker checked; starts **pending**, cannot download/export/extract until a trusted scanner approves. No antivirus or PDF extraction is fabricated. Other MIME, archives, SVG, executable conversion are unsupported.
- `recordScan` is a direct trusted-adapter method, not an HTTP route. It requires deployment-specific `scan.manage` authorization and the expected hash. The common access service intentionally has no implicit scan capability; without a configured scanner binaries remain denied.
- External collection is **disabled unless explicitly configured**. Only exact approved HTTPS origins, no URL credentials/fragments/IP literals, public IPv4 DNS answers only, no mixed private answers, no IPv6, no redirects or compression. HTTPS lookup is pinned to the checked IP while retaining hostname TLS verification; DNS, response and body are bounded. Fixture fetch/resolver injection is for tests, not caller configuration.
- Imports preserve original IDs, history, source references, ACL lists, links and license metadata as untrusted evidence. Effective visibility is **only the importing principal**. Existing IDs are never overwritten; current ACL narrowing is enforced before storing and before reading proposals. An imported `clean` string does not approve a binary. The host workflow must consume proposals through its normal review/publication contract; importing never invokes publish.

## Integration boundaries / not claimed

The owning host mounts routes/UI, supplies raw fetch with session/CSRF/space headers, mounts PVC, configures approved origins/scanner, and displays actual pending import/link changesets in its review workbench. No persistent local crawler/daemon is added. Exact OpenCode2.2.2 synthetic-message and assistant-message (including explicitly selected completed tool outputs) formats are tested against actual redacted API fixtures described in `fixtures/README.md`. For assistant messages, supply `sessionId` and `selectedToolIds` in addition to message `selectedIds`; no tool input, hidden reasoning, snapshot or native-provider field is persisted. Omission counts and author-statement/tool-output/mixed kind remain explicit, never independent execution approval. Project labels remain `projectVerified:false`, not a fabricated external mapping. Whole-session export, other versions and installation approval are not claimed. Physical deletion, retention, encryption, backup restore and CAS garbage collection are the operational-release task, not simulated here. Logical attachment replacement/versioning and actual reviewed-import consumption are implemented below.

### Consumption policy and atomicity

- Current ACL/provenance, source immutability, membership/session, source-create/propose authority and exact page bases are checked before preparation and again in core `onCreated`. Complete imported history and all archive raw sources constrain proposal provenance, including tree ancestors and older versions. Imported parent edges become reviewed dependency links and their source restrictions, so a child cannot escape parent narrowing; tree/lifecycle/license/history remains available unchanged in the read-only archive. Imported Owner/Admin/verification/scan strings do not create authority or verified evidence.
- Team/unknown namespaces cannot introduce new source/page IDs. Team sources require exact existing authorized immutable ID+content, or an explicitly registered `source.correct` replacement whose reader set is a subset of both original current upper bounds and original archive limits. An arbitrary accessible source ID is not a replacement proof. Missing registration fails `IMPORT_SOURCE_REGISTRATION_REQUIRED`; raw mismatches fail `IMMUTABLE_SOURCE_MISMATCH`.
- Only the active human owner of a personal namespace may introduce new IDs. Sources are registered through the authoritative core with **only that principal** as reader, private scope, unverified status and server-supplied actor/project. Core's atomic `onRegistered` also records the source mapping and immutable file snapshot. No page is made live during staging. A failure can leave a clearly private registered raw staging source, never half-created visible pages; retry reuses its durable mapping instead of duplicating it.
- New imported text attachments are materialized under current existing page/source bounds, or the private imported source for a new personal page. New binary `clean` labels are not trusted: `IMPORTED_BINARY_SCAN_REQUIRED`. Existing binary references must match actual server metadata and actual current clean scan. New CAS/file metadata, version chains and effect mappings commit in the same core proposal callback. File IDs/slot IDs are random; original IDs/history remain archived. Authenticated attachment references are rewritten to immutable mapped blob IDs in the reviewed candidate. Existing IDs/files/pages/ACLs are never overwritten by import.
- The archive read DTO reports `effectiveScanState`, `contentOmitted` and `omissionReason` for each file. Unapproved binary `base64` is omitted even in archive JSON; original quarantined bytes remain durable but cannot bypass the scan restriction via this read route.
- `storage_import_effects` binds one request fingerprint to one actual batch result in the same publication transaction; conflicting retries fail `IDEMPOTENCY_CONFLICT`. Simultaneous/lost-response retries recover the same batch, with no duplicate proposal or file/version metadata. Attachment association uses an atomic durable result mapping too.
- `list` now includes `slot_id,file_revision,head_revision,head_id,withdrawn,is_head`. `StoragePanel` implements replacement headers/CAS, safe text preview, immutable history labels, explicit withdrawal, actual reviewed link/import submission. Optional props `baseVersion` and `editorPageId` let the host pass the displayed authoritative document version and a target document for source-parent attachments. No static/public file URL is generated.

## Shared mutation gate and capacity admission

Construct `StorageService(pool,files,authorizer,{minimumAvailableBytes})` with a **server-controlled** reserve, default64MiB, minimum5MiB. Production uses real `statfs(root,{bigint:true}).bavail*bsize`; reserve + input bytes must be available. Low/unknown capacity fails closed (`STORAGE_CAPACITY_LOW` / `STORAGE_CAPACITY_UNKNOWN`) before CAS/reference creation. No fallback temporary store exists. A trusted `capacityProbe` callback is available only for fault tests/deployment adapters, never request DTOs. Existing reads/downloads remain available.

Every storage CAS creation/dedup/hash verification goes through `writeContent(db,bytes)` inside the **same** transaction that commits final references. This holds shared advisory gate822025 through bounded file I/O and metadata commit. Source ingestion, snapshot, upload/replacement, staged import and both core import callbacks use it. The common transaction must acquire this gate **before workspace rows**; never hold a separate outer pool client gate around nested transactions. URL collection and request-body streaming happen outside DB locks.

Physical purge/backup must hold the exclusive822025 gate. Protect original and historical `storage_blobs` hashes, slots/version references, source snapshots, `storage_imports.manifest.stagedBlobs[*].sha256`, original archived `manifest.manifest.blobs[*].sha256`, and bindings reachable through `storage_import_sources`, `storage_import_effects.result.blobMap`, `storage_attachment_links` until a coordinated authorized retention/tombstone operation has disposed of the whole graph. A tombstone on one parent is not permission to unlink deduplicated bytes retained by another slot/private archive. This module does not enable `physicalDeletionGateConfirmed` on behalf of operations.

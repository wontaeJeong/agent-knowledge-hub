This package implements IAM-004, IAM-006 and IAM-008 software boundaries. Native auth and canonical access hooks are now integrated: see [NATIVE_INTEGRATION.md](NATIVE_INTEGRATION.md), which supersedes the pending-auth/access instructions below. **Task B still requires coordinator factory/HTTP/UI/unattended-refresh integration and resolution of the documented legacy upgrade contract conflict.** No company approval, production IdP deployment, TLS deployment, or downstream agent-performance effect is claimed. These controls preserve the North Star's current-source permission ceiling across Ingest → Query → Lint and feedback; they do not evaluate knowledge quality.

## Mandatory host wiring

1. Apply migration 101 through the normal migrator, not the web process. Existing sessions receive activity rows at migration time; subsequent login MUST call `initializeSessionPolicy(db,{sessionId:sessionHash(raw),principalId,workspaceId})` in the **same transaction** as the existing `runtime_sessions` INSERT. No bearer token, CSRF token, access token, ID token, email-derived ID or client principal is accepted by this package.
2. Construct one deployment policy via `sessionPolicyFromEnvironment(process.env)` (`SESSION_ABSOLUTE_SECONDS=3600`, `SESSION_IDLE_SECONDS=1800`, `SESSION_TOUCH_SECONDS=30` defaults). All guards MUST use the same policy. Absolute ceiling is also constrained by the existing token/session `expires_at`; touching never extends it. Use the original session hash/actor binding, not a selected-space session fabricated by the browser.
3. In `OidcAuth.authenticate`, `requestGuard`'s final DB assertion, `executionSession` / `assertInteractiveGrant`, and every session-derived active-effect boundary: `await assertSessionPolicy(db,binding,policy)`. Keep its shared session/principal locks through the actual DB effect transaction. Assert again immediately before non-transactional effects. Every durable grant final assertion must still validate its parent session. DB errors propagate, never become success. For a successful **interactive** request only, call `touchSession(db,binding,policy)` in a transaction; do not touch from workers, grant execution or automated polling. `touchSession` takes parent-session then activity locks. Assertions do not lock activity rows: last-seen only moves forward, and shared activity locks would deadlock simultaneous touch upgrades.
4. Construct `new IdentityOperations(pool,policy,optionalGlobalLogoutAdapter)`. Wire `handleIdentityRequest({sessions,emergency?,directory?},ctx,method,pathWithQuery,body)` after normal authentication, current IdP revalidation, Origin/CSRF and bounded JSON parsing. `ctx` comes only from server auth. Match `/api/v1/identity/` before generic routes. It returns `{status,body}` or null. Logout/revoke never take an actor argument; the target hash is constrained to the current actor. Clear the session cookie on logout-all/current-session revocation. Product logout is committed before the optional IdP call; return `idpLogout=not_configured|failed|completed` honestly. Error mappings: `UNAUTHENTICATED`/`FRESH_DIRECTORY_HUMAN_REQUIRED`→401, `FORBIDDEN`→403, `NOT_FOUND`→404, `STALE_VERSION`/`STALE_DIRECTORY_PROOF`→409; malformed schema/input→400, DB/provider errors→fail closed.
5. Directory proof minting is server-only. Create a long-lived `DirectoryAuthority({issuer,maxAgeSeconds<=300,fetchVerifiedUserInfo})`, injecting already-verified OIDC UserInfo with its expected issuer and subject. Preserve opaque provider group IDs exactly; do not convert local Keycloak group display paths into claimed IDs. Existing admission mapping (`auth.role(info)`) stays separate. The callback must enforce OIDC response signatures, exact approved HTTPS origins, timeout/size policy and current admission. Alternatively use `signedDirectoryAuthority({issuer,endpoint,approvedOrigins,audience,publicKey,maxAgeSeconds})`: this implements bounded POST + pinned RS256 verification + exact issuer/subject/audience + freshness; no browser issuer/group proof API exists. Its transport is production HTTPS by default. Test loopback transport is not TLS deployment evidence.
6. Fetch/verify proof **outside** a write transaction, then `syncDirectoryMemberships(db,proof)` inside one. `syncDirectoryMemberships`, `projectDirectoryMemberships`, `bindDirectoryGroup`, `denyGroupMembership`, and `setManualGroupMembership` MUST receive the transaction client, never a Pool/autocommit query interface. The transaction-local projection flag prevents directory rows becoming manual grants. Before **every** current-rights read (`effectiveAccess`, canonical SQL role/read helpers, source ACL consumers, share/group checks and final job effect), run `projectDirectoryMemberships(db,principalId)` in that transaction. This removes stale/disabled/changed-issuer/binding-revision paths immediately when rights are checked. An optional periodic sweep may call it without principalId, but is not a substitute for the mandatory guard. Admission and `access_principals.active` are never changed. Existing/revoked direct grants are untouched. Manual canonical rows at migration are preserved independently.
7. Wire manual group add/remove to `setManualGroupMembership(db,ctx,groupId,targetId,active,canonicalGroupAdmin)`; it handles an existing canonical ON CONFLICT no-op and explicitly authorized regrant. At minimum, every removal must call `denyGroupMembership` even when its canonical row is already absent. Ordinary canonical DELETE also creates a tombstone through migration 101's trigger. No ordinary INSERT clears a deny. `canonicalGroupAdmin` checks current human team Owner or current canonical `space.admin` in the **same** namespace (not reviewer, another team's Admin, or agent token). `bindDirectoryGroup` revisions changes and revokes only contributions from that binding; reactivation requires fresh proof. HTTP directory configuration uses pre-approved `{key,issuer,externalGroupId,groupId,label}` options at server construction, not arbitrary request values.
8. Emergency construction requires explicit `platformEmergencyApproverIds` (no space/company Owner inference), policy, `assertFreshHuman` and `assertSourceUpperBound`. The freshness callback refreshes verified directory state; the package additionally checks a matching active human proof in DB, <=5 minutes and unexpired. Approval refreshes both requester and approver. The original-source callback must validate the requester's **complete** page/source ancestry, lifecycle/restrictions/holds without recursing into emergency authorization. No raw-readers mutation is allowed.
9. Wire `emergency.emergencyEffectiveCapabilities(db,ctx,pageId,canonicalConstraintActions)` in the existing canonical **resource-scoped** authorizer, not a second authority. Its result is a scoped intersection of fixed `knowledge.read|queue.triage|triage.manage`, independent approval, fixed expiry, active current humans, and the host's current non-role constraints. It may supplement a missing action role for this exact page only; never synthesize `Admin`, `Owner`, `space.admin`, agent-token powers, raw source readers, publish, deletion, legal-hold or model-egress bypass. Keep every existing source/provenance/egress/final-effect assertion. Never union this into unscoped `effectiveAccess` capabilities or persist it in grants. Append-only events record request/approval/rejection/revocation/use; expired pending/approved rows are presented as expired without inventing approval. No renewal API exists.
10. Render `IdentityManager` with the existing CSRF/authenticated generic API **function adapter**, not the `OperationalApi` object. Props: `api`, `onExpired`, optional `emergencyEnabled`, `directoryEnabled`, `pageOptions` (current permitted scoped document options). The UI has Korean forms, 25-item paging, own-session counters, server statuses, no approver/operator identity field and no raw credential/proof input. Only enable optional sections when their server services are configured. Actual browser/390+1440 verification remains for the host; current frontend tests are server-rendered structure checks, not browser interaction evidence.

Local Keycloak exception: `DirectoryAuthority` and server-only directory HTTP configuration may explicitly set `allowLoopbackHttp=true` for an already-verified loopback HTTP issuer (`localhost`, `127.0.0.1`, `::1`) only outside production. Pass the same option as the final server-only `bindDirectoryGroup` argument. No browser flag controls this and production always rejects it. Signed external endpoints and logout bridges remain HTTPS-only.

Existing `AccessService.setGroupMembers` currently uses bulk DELETE/INSERT replacement. The host must replace this with an explicit manual-provenance update using `setManualGroupMembership` (or diff the manual set and deny removed members). Do not accidentally turn unchanged directory-visible members into permanent manual grants, and do not bulk-delete unchanged rows then leave their tombstones uncleared. `setManualGroupMembership(...,true)` is an explicit independently authorized product regrant, not an automatic directory sync.

## Optional global IdP logout

`ApprovedHttpsGlobalLogout({endpoint,approvedOrigins,issuer,fetch?})` calls a real configured revocation bridge with issuer/subject and requires a bounded explicit `{revoked:true}` acknowledgement. A server-injected workload/mTLS transport can authorize the bridge. No redirect URL is claimed as completed logout. Without an approved bridge, product logout-all still invalidates all actor sessions, all actor `runtime_execution_grants` and their ephemeral canonical credentials before acknowledging, but says external logout is unconfigured.

# 제품 로드맵

기존 239개 요구사항을 보존하고 CORE-001~012 핵심 순환 수용 기준을 추가해 총 251개 항목을 추적한다. 단계는 구현 순서이고 운영 범위 축소가 아니다. 모든 항목의 프로덕션 상태는 미검증이다. 로컬 시연은 UI와 도메인 일부가 동작함을 뜻하며 전체 수용 기준 통과가 아니다.

## 다음 구현의 우선순위

제품의 장기 기준은 [North Star](LLM_WIKI_CORE.md), 효과를 입증할 방법은 [평가 계약](EVALUATION.md)이다. 아래 항목은 목표 연결을 위한 계획이며 구현/평가 완료 선언이 아니다. 기존 P0~P3와 전체 요구사항 이행표는 계속 유효하다.

### 로컬 개인 위키와 지식 컴파일의 통합 격차 (2026-10-29)

PR #7의 합성 로컬 위키 커넥터는 개인 작업본의 동기화·충돌·단일 페이지 공유 제안을 시연한다. 반면 `src/domain/wiki.ts`는 브라우저 상태에서 원본 기반 다중 페이지 컴파일·발행·질의 재편입·Lint를 시연한다. **두 경로는 아직 연결되지 않았으며, 동기화 성공은 Knowledge Compounding의 검증이 아니다.**

**로컬 커넥터 상시 실행은 제품 범위에서 제외하며 미구현/미래 과제로 추적하지 않는다.** 연결 중 자동 동기화와 종료 시 미전송 변경 보존·재연결 재개만 지원한다. 서버의 지속 작업·재시도·예약 유지관리 요구사항과 P2 운영 게이트는 그대로 유지한다.

[통합 계획과 KI-01~08 수용 시나리오](KNOWLEDGE_INTEGRATION.md)를 다음 수직 통합의 작업 기준으로 사용한다. [ADR 004](adr/004-unified-knowledge-service.md)는 **제안** 상태이며 최종 아키텍처 승인/구현이 아니다.

| 단계 | 통합에서 우선 확인할 결과 | 아직 주장할 수 없는 것 |
| --- | --- | --- |
| P0 | Raw Source/지식/개인 draft/공유 변경 집합의 정본·권한·버전/철회 계약, ADR 검토 | 서버 ACL·원본 진위 |
| P1 | 웹·MCP가 공통 지식 서비스의 발행본을 조회하고 원본 검증 → 기존 지식 재구성 → 의존 집합 검토/발행 → Query/Lint 연결 | 현재 로컬 JSON 공유 발행만으로 서버 다중 사용자 원자성·의미 품질 |
| P2 | 작업 결과의 근거 있는 환류와 재검토, 원본/권한 철회 전파, 평가 계약의 대조 실험 | 증거 없는 성능 향상·무인 운영 완료 |

KI는 기존 251개 수용 기준을 추가·대체하지 않으며 실행 결과가 없는 설계 사례다. 제품/보안/모델 품질 검증은 별도 완료 조건으로 유지한다.

### 로컬·개인·팀 공간 권한 확장 (2026-10-30, 설계 제안)

[권한 모델](ACCESS_CONTROL.md)과 [ADR 005](adr/005-github-style-access-control.md)에 사용자/팀 namespace·접근 그룹·공간별 Read/Triage/Write/Maintain/Admin, Private/Team/Company, 자료 제한·독립 검토·위임 상한·OIDC/3역할 이관을 정의했다. 현재 서버 권한을 새 모델로 교체한 것은 아니다. 기존 GOV-003/004·ACL-001~014·REV-003~006/009·INT-001/002/006 및 운영 요구사항을 구체화하며, 기존 251개 항목의 수·수용 기준·미검증 상태는 유지한다.

P0에서 정책/소유권·이관 계약을 확정하고, P1에서 서버 권한·관리/검토 UI·개인 커넥터/제한 토큰을 공통 서비스로 연결한다. P2에서 AC-01~24와 기존 인수 시험의 실제 권한/철회/발행 경쟁·반출/복구 근거를 검증한다. 이 순서는 첫 실사용 필수 요구사항을 제외하는 근거가 아니며, 권한 기능이 미완료이면 출시 조건도 미충족이다.

### 목표 연결 단계와 종료 근거

- **P0 기반 계약:** 세 층, 권한, 주장/근거/시간/경험 계약과 사전 평가 기준을 확정한다. 문서 합의는 서버 통제 구현의 증거가 아니다.
- **P1 기능 통합:** 실제 자료·모델·서버 저장소에서 Ingest → Query → Lint → 재편입을 연결하고 버전·계보·검토 증거를 남긴다. API/MCP는 동일 서비스 계약의 소비 경로로 구현한다. 오프라인 성공을 의미 품질로 대체하지 않는다.
- **P2 운영 준비:** 무인 정련·성과 환류·삭제/권한 전파·복구를 검증하고 누적/시간/상충/후속 작업 대조 실험을 반복한다. 운영 수용 조건과 사전 합의한 품질·안전 기준을 모두 충족해야 종료한다.
- **P3 조직 확대:** 새로운 도구·자료·규모·환경으로 확장하면서 기존 지식과 에이전트 성능의 비회귀를 재측정한다. 규모 확대가 품질 개선을 자동 의미하지 않는다.

미래 기능은 관련 요구사항과 평가 시나리오에 연결해 별도 구현한다. 이 장기 계획 때문에 지금 모든 기능을 추가하거나 기존 요구사항을 제외하지 않는다. 아키텍처가 장기 목표와 충돌하면 North Star의 변경/예외 절차에 따라 트레이드오프를 기록한다.

1. 기반 권한·자료 등급·사내 UI 계약과 원본 보존 계약을 확정한다.
2. Ingest → Query → Lint의 연속 순환을 실제 사내 모델과 서버 저장소로 구현·평가한다. MCP만 연결하고 지식 누적 엔진을 후순위로 미루지 않는다.
3. 인증된 MCP 도구와 업무 맥락 선택, 실행 결과 환류를 공통 서비스에 연결한다.
4. 지속 작업·무인 일정·삭제와 권한 전파·감사·복구·성능 게이트를 충족한다.

현재 오프라인 편입은 구조 규칙, 질문은 발행본 발췌, Lint는 구조·명시 사실 검사다. 선택적 모델 편입·답변 서버 코드를 제공하며 실제 사내 모델 품질 검증은 남아 있다. 상세 범위는 [핵심 컨셉](LLM_WIKI_CORE.md)과 [에이전트 인터페이스](AGENT_INTERFACE.md)를 따른다.

## 현재 데모의 한계

모델을 설정하지 않으면 LLM을 호출하지 않는다. 일정은 자동 실행되지 않는다. 역할·공유·데이터는 브라우저 로컬 시연이다. 의존 문서 집합의 일괄 발행은 현재 단일 로컬 상태 전이이며 다중 탭·다중 사용자와 DB 트랜잭션은 서버에서 구현한다. 수동 편집은 현재 즉시 발행하므로 운영용 초안 흐름으로 교체한다.

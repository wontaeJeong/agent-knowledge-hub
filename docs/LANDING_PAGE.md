# 웹 첫 진입과 위키 소개

2026-10-30 사용자 요청: 웹에 처음 접근했을 때 랜딩페이지를 제공하고, 왜 위키를 쓰는지와 Memory·RAG와의 차이를 명확히 설명한다. 기준은 [North Star](LLM_WIKI_CORE.md)이며 제품 목표의 의미는 바꾸지 않는다.

## 메시지와 읽는 순서

“대화와 업무 결과를, 다음에 다시 쓸 수 있는 지식으로.”를 첫 화면에 둔다. 원본 요약의 수보다 기존 결론·조건·연결의 유지와 재사용을 설명한다.

1. 목적과 합성 예시: 일주일치 팀 대화·로그가 기존 배포 가이드의 변경 후보로 연결되는 모습.
2. 왜 Wiki인가: Memory는 대화·선호·과거 상태의 기억, RAG는 관련 근거 검색과 답변 지원, LLM Wiki는 종합한 지식의 영속적 유지·갱신에 초점을 둔다는 비교표.
3. 같은 입력을 활용하는 세 방식의 선택형 예시. 실제 처리 결과가 아닌 합성 설명이며 변경 버튼은 모델/API를 호출하지 않는다.
4. Ingest → Review → Query → Lint & Feedback. 원본·위키·유지 규칙과 질문 결과의 재편입을 설명한다.
5. 근거/조건, 개인·팀/원본 권한, 사람/에이전트의 공동 활용 원칙. FAQ와 시작 경로.

Memory·RAG·Wiki는 배타적인 제품 분류가 아니다. Memory/RAG가 종합·갱신할 수 없다고 단정하지 않으며, Wiki의 검색/Memory 병용을 명시한다. 검토 승인과 진위 보장, 파생 답변과 독립 증거를 구분한다. 자동 정리·자연어 모순 탐지·무인 운영·에이전트 성능 향상을 검증된 성과로 홍보하지 않는다. 현행 기능과 장기 확장은 화면에서도 분리한다.

## 진입 계약

| 주소 | 화면 | 연결 |
| --- | --- | --- |
| `/`와 소개 앵커 | 공개 랜딩 | 인증·API 호출 없음. 서버 중단/정적 실행에서도 소개를 읽을 수 있음 |
| `/?app=1` | 기존 서버 지식 공간 | 세션 확인 후 기존 SSO 또는 보호된 UI. 인증 없는 데이터 접근을 허용하지 않음 |
| `/?demo=1` | 기존 합성 데모 | 서버 인증/정본과 별개의 브라우저 저장 시연. 기존 `#/wiki/...` 등 hash 경로 유지 |
| `/auth/login`, `/auth/callback` | 기존 OIDC 흐름 | 로그인 성공 시 고정 주소 `/?app=1`로 복귀. 사용자 입력으로 redirect 대상을 지정하지 않음 |

`demo=1`이 두 플래그의 동시 입력보다 우선한다. 그 밖의 값은 앱을 암묵적으로 활성화하지 않는다. 랜딩은 이미 로그인한 사용자에게도 표시하며 “지식 공간 열기”로 이동할 수 있다. 운영 UI의 홈/로그아웃은 `/` 소개로 돌아온다. query 기반 진입을 사용해 기존 정적 실행기·Nginx·서버의 root 제공 계약을 유지한다. 페이지 전체 이동으로 앱을 전환하고 두 클라이언트를 지연 로드하므로 소개의 앵커와 데모 hash 라우터는 서로 관여하지 않는다.

## 표현과 접근성

- 기존 육각형·책 심볼, `BrandIcon`, plum 의미 토큰과 설치된 폰트/fallback을 사용한다. 외부 폰트·이미지·분석·모델 요청을 추가하지 않는다.
- 라이트/다크는 저장된 테마, 시스템 선호, 기본 다크 순으로 선택한다. 저장이 차단돼도 화면과 테마 전환은 동작한다. 테마는 랜딩 컨테이너에 적용해 기존 앱의 테마 처리를 변경하지 않는다.
- 단일 h1, 본문 바로가기, 의미 있는 비교표/caption/scope, 키보드 스크롤 영역, 일반 버튼의 `aria-pressed`, 결과 영역의 `aria-live`, 기본 details/summary와 초점 표시를 제공한다.
- 좁은 화면에서 본문은 한 열로 배치한다. 비교표만 내부 가로 스크롤을 제공하며 페이지 전체 가로 넘침을 허용하지 않는다.
- 소개는 기존 React 클라이언트 렌더링이다. 제목/설명 메타데이터는 정적 HTML에 포함하지만 본문의 서버 렌더링·검색엔진 노출을 검증한 것은 아니다.

## 검증과 제품 범위

관련 기존 기준은 GOV-001(서비스 목적), CORE-002~007(설명하는 순환), CORE-009(에이전트 경계)다. 이 작업은 해당 기준의 서버/운영 인수 상태를 완료로 바꾸지 않는다. 새 근거로 기존 지식을 갱신하는 목적을 사람에게 설명하는 진입 UX이며 지식 엔진·원본 ACL·승인·발행 규칙은 변경하지 않는다.

진입 모드/실제 CTA 목적지, API 없는 초기 렌더링, 소개 앵커 연결, 기존 도메인 회귀와 전체 기본 검사를 검증한다. OIDC 회귀는 로그인 성공 redirect가 서버 지식 공간으로 이어지는지를 함께 확인한다. 화면 증거와 실행 범위는 [인계](AGENT_HANDOFF.md)와 `pr-assets/landing/`에 기록한다.

# LLM 사내 위키 검토와 요구사항

2026년 10월 26일 기준으로 작성한 제품 설계 검토와 요구사항 기준안이다. 목표는 직원의 LLM 업무 산출물을 근거와 권한이 유지되는 사내 위키로 축적하고, AI 매니저가 지속적으로 관리하며 다른 사람과 에이전트가 재사용하게 만드는 운영 서비스다.

## 주요 결정

- 사내 서비스의 전체 요구사항을 유지하며 초기 데모는 동일한 제품 코드로 일부 흐름을 검증한다.
- 공개 프로젝트 전체를 그대로 채택하지 않고 라이선스와 기능 계약을 검증한 구성요소부터 재사용한다.
- 산출물 원본, 위키 버전, 검토 변경 묶음, 발행 집합 및 관리 실행 이력을 분리한다.
- 원본의 권한을 파생 위키·검색·답변·과거 버전·첨부에도 적용한다.
- Daily 및 Weekly 매니저는 사람과 같은 검토·버전·발행 체계를 사용한다.
- 실제 사내 운영 전 인증·보안·관측·복구·운영 인계까지 완료 조건에 포함한다.

## 요구사항의 구분

전체 239개 중 **필수 224개**는 첫 실제 사내 운영 이전의 조건이다. **확장 12개**는 해당 기능 또는 확대 범위를 제공하기 전의 조건이고 **선택 3개**는 조직 정책으로 활성화한다. 선택 기능은 사내 전체 링크 공유·외부 게스트·익명 공개다. 기본 비활성 기능의 API·URL·MCP·작업 차단은 첫 운영부터 필요하다.

35개는 통합 인수 시나리오의 수이며 개별 테스트 케이스 총수가 아니다. 각 요구사항의 수용 기준과 함께 시험한다. 모든 요구사항은 미구현, 모든 인수 시나리오는 미실행으로 시작한다.

## 검토 상태

제품·설계 관점의 검토와 공개 저장소 6개의 36개 파일 표본 정적 검토를 수행했다. 후보의 전체 코드 감사, 설치·테스트 실행, 실제 사내 SSO·모델 연결, 부하·복구 시험은 수행하지 않았다. 문서에 있는 동작과 수치는 이 서비스의 구현 또는 시험 통과를 뜻하지 않는다.

사내 정책과 실제 도구 버전·사용 규모·운영 인력은 review.md의 미확정 항목으로 남겼다. 이에 의존하는 성능·품질·RPO·RTO 수치는 제안 기준이다. 코드 채택 및 운영 개시 전 해당 결정과 실제 검증 결과를 기록한다.

## 운영 전 판정

기능 화면 완성만으로 출시 완료 처리하지 않는다. 필수 요구사항, 접근 행렬, 중요 AI 품질, 실제 도구 연동, 중대 보안 결함 조치, 업그레이드·복원, 운영자 인계 결과가 함께 있어야 한다. 월간 가용성처럼 운영에서만 측정할 수 있는 값은 계측과 대응 체계를 먼저 검증하고 실제 운영으로 추적한다.

## 기준 문서 재생성

build_requirements.py와 build_acceptance.py는 이 문서 묶음의 생성 보조 코드다. 서비스 구현 코드나 실행 가능한 인수 테스트는 아니다. 요구사항 변경 시 두 스크립트를 순서대로 실행하고 추적 관계와 문서를 다시 검토한다. source-audit.json은 검토한 시점의 스냅샷이므로 최신 코드 검토 없이 새 커밋으로 바꾸지 않는다.

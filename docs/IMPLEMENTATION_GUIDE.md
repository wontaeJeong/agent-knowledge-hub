# 웹 자료 편입 · 조직 접근 관리 구현

2026-10-30. 이 문서는 새 서버 코드의 실행 계약이다. [권한 설계](ACCESS_CONTROL.md), [자료 편입 설계](DATA_INGESTION.md), [대화 예제](CONVERSATION_IMPORT.md)와 함께 읽는다. 기존 251개 요구사항·35개 인수 시나리오의 전체 완료 또는 운영 인수를 의미하지 않는다.

## 사용 흐름

1. OIDC로 로그인한다. **공간 · 접근 멤버**에서 개인/조직 공간을 선택한다. Organization → Team(접근 그룹) → 지식 공간의 구조다.
2. **자료 넣기 · 자동 정리**에서 텍스트를 붙이거나 파일을 넣는다. 파일은 선택한 공간 안의 본인 수집함에만 저장된다. 같은 공간의 Admin도 타인의 개인 수집함을 열 수 없다.
3. 서버가 입력을 분석한다. 형식·인코딩·시간대·기간·CSV 컬럼·제외할 발언을 확인하고 누락·불확실성 안내를 확인한다. 선택을 바꾸면 새 분석 revision이 필요하다.
4. 자동 정리를 실행한다. 서버 작업이 기존 접근 가능 지식과 비교해 여러 주제·기존 페이지의 전체 변경 후보를 만든다. 모든 발언을 근거 또는 명시적 제외로 처리한다. 제안·결정 진술·실행 완료 주장을 구분하며 실행 사실로 자동 승격하지 않는다.
5. 정리 결과는 개인 검토 후보다. 대상 독자·검토자·원본 공개 권한 확인을 명시하고 **원본 공개 검토**를 요청한다. 지정된 독립 검토자에게 선택된 원본과 후보만 보인다.
6. 별도 권한을 가진 검토자가 원본 공개를 승인하면 공유 원본 스냅샷과 변경 집합을 만든다. **변경 검토**에서 독립 지식 승인 후 전체 변경을 원자적으로 발행한다. 원본 공개 승인 자체는 위키 발행이 아니다.

브라우저 탭을 닫아도 서버의 DB 작업은 남는다. 자연 세션 만료·로그아웃·현재 역할 회수·IdP 확인 실패는 결과 반영을 멈춘다. 재로그인 후 재개하거나, 입력/정책이 바뀌었으면 새 작업을 만든다. 데스크톱 앱은 이 흐름에 필요하지 않다. OS 전용 자료 수집·완전 로컬 분석은 후속 어댑터이며 로컬 상주 daemon을 추가하지 않는다.

## 설정과 이관

기존 OIDC 설정과 `migrate:server`를 그대로 사용한다. 마이그레이션 006은 편입, 007은 접근 관리 테이블/공통 실효 역할 함수를 추가한다. API 프로세스는 마이그레이션하지 않고 정확한 스키마/체크섬을 확인한 뒤 실행한다. 배포 전에 기존 DB를 백업하고 별도 마이그레이션 작업을 실행한다.

| 환경 변수 | 기본값 / 의미 |
| --- | --- |
| `IMPORT_WORKER_ENABLED` | true. API 안의 서버 worker 실행. false이면 별도 `npm run start:import-worker` 프로세스가 필요 |
| `IMPORT_DISCLOSURE_REVIEWERS` | 빈 값. 원본 공개 판단 권한을 운영 정책으로 지정한 내부 principal ID의 쉼표 목록. 현재 reviewer/Maintain/Admin도 필요. 빈 값이어도 개인 분석은 가능하나 팀 공개는 차단 |
| `ACCESS_BOOTSTRAP_OWNERS` | 빈 값. 기존 workspace를 조직 관리로 전환할 검증된 내부 principal ID. `/me`의 ID를 운영자가 확인해 명시. reviewer를 자동 Admin/Owner로 승격하지 않음 |
| `ACCESS_ALLOW_ORG_CREATE` | false. true이면 OIDC 입장 정책을 통과한 인간이 Organization 생성 가능. 생성한 조직의 Owner만 됨 |

**기존 공간의 전환은 명시적이다.** 운영자가 초기 Owner를 바인딩한 뒤 그 사용자가 웹에서 기존 멤버 이관을 확인한다. reader→Read, editor→Write, reviewer→Maintain로 옮기고 기존 reviewer를 지정 지식 검토자로 등록한다. 선택된 초기 Owner만 Admin이 된다. 원본/페이지 ACL은 넓히지 않는다. 전환 후 OIDC 그룹은 입장 자격이며 제품 역할은 DB grant로 결정한다. 기존 그룹 재로그인이 수동 회수를 되살리지 않는다. 미전환 공간은 기존 OIDC 매핑을 계속 사용한다.

새 조직은 기본 공간 역할 none, 새 공간은 Private, 개인 공간은 본인 전용이다. 초대 대상은 이 배포에서 로그인해 검증된 신원이며 이메일/사용자 입력을 신원으로 신뢰하지 않는다. 개인 공간에 타인을 초대할 수 없다. Team 공개도 원본/파생본의 좁은 ACL을 변경하지 않으므로 공간에 들어왔어도 읽을 수 있는 문서가 없을 수 있다.

## 저장·자원 한도

초기 App1/DB1에서는 추가 broker/blob store 없이 **제한된 텍스트 원본을 PostgreSQL bytea 조각**으로 보관한다. DB 백업/복원 대상에 원본이 포함된다. 범용 첨부 저장소가 아니며 대용량 파일은 후속 객체 저장소 어댑터가 필요하다.

- 파일 25 MiB, 묶음 32개/100 MiB, 조각 256 KiB, 사용자 100묶음/예약 250 MiB, 공간 1 GiB.
- ZIP 항목 2,000개, 해제 합계 200 MiB, 중첩/암호화/심볼릭 링크/경로 탈출/실행·HTML·SVG 파일 거부. CRC/크기 검증. 첨부를 실행하거나 외부 링크를 가져오지 않음.
- 파서 별도 자식 프로세스 256 MiB V8 heap/30초. 컨테이너 전체 메모리 격리는 별도 운영 자원 정책.
- 최대 20,000 레코드, 모델 입력 청크 약 100k bytes, 실행 모델 호출 최대 20회, 최대 5회 lease 회수, 실행 위임 1시간/현재 세션 상한. 모델 호출 재시도는 추가 비용을 낼 수 있음.
- 현재 추적은 작업 상태/모델 호출 횟수다. 공급자 토큰/금액 정산·청크별 모델 결과 재사용·자동 TTL 보존 정리는 아직 없음. 사용자가 수집함을 삭제해 공간을 회수할 수 있음.

삭제는 원본·개인 분석/실행 기록을 지우고 해당 공유 원본을 철회한다. 파생 페이지/과거 버전의 모든 물리 바이트·DB 백업·이미 내려받은 평문을 전역 삭제하는 기능은 아니다. 현재 ACL을 통해 이후 보호 요청을 차단한다. 개인정보의 보존·백업 삭제 정책은 배포 운영자가 별도로 확정해야 한다.

## 검증

- `npm run check`: 기존 도메인/커넥터 테스트, 편입 순수 테스트 13개, 요구사항 검사, 서버 타입 검사, 빌드, 정적 HTTP smoke.
- `npm run test:server` + 실제 PostgreSQL: 편입 서비스/HTTP/SDK MCP 14개와 접근 관리 6개를 포함한 서버 회귀. GitHub Actions의 PostgreSQL job이 기본 증거다.
- 로컬 보조 DB 검증에는 WASM PostgreSQL(PGlite)을 사용했다. 네이티브 PG와 세션 시작 옵션/동시 연결 동작이 동일하지 않으므로 네이티브 PG CI를 대체하지 않는다.
- 브라우저 검증은 합성 한글 대화 + loopback OIDC UserInfo + 결정적 모델 계약 fixture를 사용한다. 실제 외부 LLM 의미 품질/사내 SSO 인수·실제 고객 내보내기 호환/장애·복원·부하 수용은 별도 검증이다.

접근 회수·원본 공개·본문/기준/전체 모델 입력·현재 정책 검사는 저장과 발행에서 다시 수행한다. 권한 관리 변경은 초기 배포의 단순성을 위해 workspace 잠금을 일정한 순서로 보수적으로 직렬화한다. 큰 조직의 처리량 최적화는 측정 후 영향 공간별 잠금으로 분리한다.

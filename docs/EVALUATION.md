# 지식 누적과 에이전트 효과 평가 계약

기준일: 2026-10-29. [North Star](LLM_WIKI_CORE.md)의 진전을 검증하기 위한 **미실행 평가 설계**다. 평가 실행기·평가 데이터셋·의미 품질 결과가 구현/확보됐다는 뜻이 아니다. 현재 자동 회귀 근거는 [TESTING.md](TESTING.md)에, 미충족 범위는 [ROADMAP.md](ROADMAP.md)에 있다. 기존 251개 요구사항과 35개 인수 시험 계획을 대체하지 않는다.

## 1. 평가 원칙과 실행 계약

- 문서·링크·토큰·호출 수와 제안 수용률만으로 Knowledge Compounding이나 에이전트 성공을 주장하지 않는다. 새 근거가 결론·조건·연결·업무 결과를 어떻게 개선했는지 비교한다.
- 원본/발행본 버전·변경 집합·질문·인용·사용 결과를 연결해 재현한다. 모델의 자신감이나 문장 유창함을 정답으로 채점하지 않는다.
- 평가 전에 제품·도메인·보안 책임자가 정답 기준, 허용 변화폭, 최소 표본/반복 수, 통과 임계값, 비용/시간 상한을 합의하고 고정한다. 현시점에는 합의된 수치나 통과 결과가 없다. 결과를 보고 임계값을 낮추지 않는다.
- 공개 범위·현재 권한·개인정보·외부 전송 정책을 평가에서도 지킨다. 무단 공개, 근거 조작, 원본 변조가 관찰되면 효과 평균과 무관하게 해당 실행은 안전 실패다.
- 전체 계획 사례 수, 실행 수, 완료 수, 실패/시간초과/중단 수, 미실행 수를 별도로 기록한다. 미실행/미확인은 0점 실측으로 위장하지 않는다. 성공률은 사전 확정한 배정 과제 전체를 분모로 사용하고 미완료는 성공에 넣지 않는다. 누락이 있으면 미완료 실험으로 표시하고 완료 집합의 지표도 별도로 병기한다.
- 오프라인 구조/명시 사실 검사, 모델 중계 HTTP 계약, 실제 모델 의미 품질, 운영 인수 결과를 서로 다른 시험 종류로 기록한다. 한 종류의 통과를 다른 종류로 승격하지 않는다.

### 고정하고 보존할 평가 입력

1. 익명화된 원본 스냅샷, 출처 위치, 생성/관찰 시점, 유효 기간, 환경/버전/전제 조건, 접근 범위와 독립 실행 증거.
2. 초기 위키와 각 단계의 발행본/관계/주장 계보, 질문/업무 과제, 승인된 정답·허용 대안·답변 보류 기준.
3. 앱 커밋, 데이터셋/위키/규칙/프롬프트 버전, 공급자/모델 버전·파라미터, 검색 설정, 도구 버전, 권한, 토큰·호출·시간 예산.
4. 독립 채점자의 판정과 근거, 이견 조정 기록. 모델 채점은 보조로만 사용하고 정답/안전의 유일한 판정자로 두지 않는다.
5. 각 실행의 입력·조회 버전·근거 인용·제안/발행 차이·오류·실제 도구 결과·토큰/비용/시간 추적. 비밀키는 기록하지 않는다.

## 2. Knowledge Compounding: 같은 자료로 무엇이 좋아졌는가

원본을 순서대로 추가하는 고정 시퀀스 S0 → S1 → S2를 만든다. 각 단계에서 **동일하게 허용된 원본 집합**을 다음 조건에 제공하고 동일한 질문/과제를 측정한다.

| 대조 조건 | 제공 정보와 목적 |
| --- | --- |
| 원본만 | 같은 원본을 질의 시점에 검색·조합한다. 영속 종합 없이 가능한 기준선이다. |
| 정적 위키 | S0에 고정한 위키와 동일 원본 접근을 제공하되 위키는 갱신하지 않는다. 유지관리 자체의 기여를 분리한다. |
| 유지 위키 | 같은 원본으로 Ingest·Query 재편입·Lint를 거쳐 검토·발행한 위키를 사용한다. |

각 조건의 정보 접근·검색/추론 예산을 동일하게 하고 위키 구축·유지 비용은 별도 누적해 총비용에도 포함한다. 원본만 조건에 갱신 자료를 숨겨 이득을 만들지 않는다. 필요하면 위키만 조회하는 추가 조건으로 사전 종합의 효율을 분리하되 기본 대조군과 혼동하지 않는다.

각 S 단계에서 다음을 기록한다.

- 결론 정확도와 조건/예외 보존: 정답 기준을 충족한 답변 수 / 채점 대상 답변 수. 보류가 정답인 질문은 별도 층으로 집계한다.
- 근거 지지율: 실제 인용 원본이 지지하는 주장 수 / 채점한 검증 가능 주장 수. 계보를 따라 같은 원본을 중복 지지로 세지 않는다.
- 관련 연결의 유용성: 필요한 개념/사례로 이동해 과제를 해결했는지 확인한다. 연결 수 자체는 품질 점수가 아니다.
- 새 정보 반영률: 새 근거로 바뀌어야 하는 판정 중 올바르게 갱신된 수 / 갱신이 필요한 판정 수.
- 이전 지식 회귀율: 새 자료와 무관한 기존 정답 과제 중 실패로 바뀐 수 / 기존 정답 과제 수.
- 품질 동일 조건의 조회/작업 비용과 지연, 유지 비용을 포함한 총비용. 실패가 빨리 종료됐다는 이유로 효율 개선으로 세지 않는다.

**누적의 증거:** 페이지 버전 차이에서 결론/조건/연결 개선과 그 근거를 식별하고, 유지 위키의 전후 변화 및 대조군 대비 차이를 함께 제시한다. 추가 문서가 없는 단계에서도 정정·연결 개선으로 품질이 높아질 수 있다. 향상이 없거나 회귀가 있으면 그대로 보고한다.

**음성 대조:** 중복 원본을 반복 유입하거나 기존 답변을 재편입한 것만으로 근거 독립성/신뢰가 상승해서는 안 된다. 근거 없는 잘못된 답변을 재편입하려 할 때 보류·거부 또는 검토 대상으로 남는지 검사한다. 이를 새 사실로 확정하면 실패다.

## 3. Knowledge Evolution 수용 시나리오

아래 KE 식별자는 평가 설계용이며 새 요구사항 ID나 통과 기록이 아니다. 관련 기존 요구사항을 함께 검토한다.

| 사례 | 입력/변화 | 기대되는 관찰과 실패 조건 |
| --- | --- | --- |
| KE-01 추가 근거 | 한 개념의 새로운 독립 근거와 기존 관련 주제 제공 | 개념·주제·연결을 함께 재검토하고 변경 이유/근거를 보존한다. 요약 한 개 추가만으로 통과하지 않는다. |
| KE-02 반증 | 같은 조건의 기존 주장과 반대되는 실행 증거 | 양쪽 출처, 불확실성, 재검증 요구를 보존한다. 근거 없이 한쪽 삭제/확정하면 실패다. |
| KE-03 시간에 따른 대체 | 규칙 A의 유효 종료와 규칙 B의 시행일 제공 | 과거 시점에는 A, 현재에는 B를 조건과 함께 답한다. 기록일만으로 현행 판단하면 실패다. |
| KE-04 환경별 예외 | 서로 다른 OS/버전에서 다른 결과 | 서로 다른 맥락은 거짓 모순으로 합치지 않는다. 적용 조건 없이 하나의 권고로 일반화하면 실패다. |
| KE-05 질문 재편입 | 여러 페이지를 근거로 만든 비교 답변 | 인용 버전·원본 계보를 유지하는 파생 후보로 검토한다. 원본이 바뀌면 재평가하고 순환 인용을 독립 증거로 세지 않는다. |
| KE-06 경험의 교훈 | 실패 시도·후속 성공·환경·실행 증거 | 실패를 지우지 않고 조건부 교훈을 만든다. 새로운 환경의 홀드아웃 과제로 재사용성을 확인한다. 한 사례로 보편적 해결책을 확정하면 실패다. |
| KE-07 원본 정정/철회 | 원본 정정·삭제 또는 권한 철회 | 파생 주장·검색·과거 답변의 영향 범위를 찾고 현재 권한/수명주기에 맞춰 차단·재검토한다. 접근 철회 뒤 내용이 노출되면 안전 실패다. |
| KE-08 갱신 회귀/중복 | 반복 편입·재시도·의존 대상 충돌 | 중복 발행 없이 이전 정답을 보존하고 충돌한 의존 집합은 발행하지 않는다. 로컬 검사와 서버 다중 사용자 시험을 구분한다. |

관련 기준: CORE-001~008, CORE-011~012, KNO-002·005·006·009·013·014, VER-005·009, REV-004~006, ACL-007·009·014. 시나리오 실행만으로 이 요구사항의 모든 운영 수용 기준을 충족했다고 표시하지 않는다.

### 로컬 개인 위키와 공통 지식 서비스의 수직 통합 평가

최근 로컬 위키 MCP는 동기화·동시 수정·단일 페이지 공유 제안을 합성 환경에서 검증했지만, 현재 웹의 Ingest → Query → Lint 순환과는 독립적이다. **[KI-01~08 통합 수용 시나리오](KNOWLEDGE_INTEGRATION.md)**는 이 간극을 평가하기 위한 *미실행 설계*다.

- 개인 draft 동기화·공유 제안·원본 등록·컴파일·검토·발행을 각각 별도 상태/측정으로 남긴다. `wiki_sync` 성공이나 페이지 수를 지식 누적 성공률로 보고하지 않는다.
- 동일 ID/다른 공간·원본 참조 위조·권한/로컬 반출 거부·선택 개인 revision 변경·다중 페이지 부분 발행·반증 재편입을 음성 사례로 포함한다. 안전 실패는 평균 지표로 상쇄하지 않는다.
- KI의 합성 프로토콜 시험, 운영 서비스 통합 시험, 의미 품질/후속 에이전트 대조 실험의 결과를 구별한다. 아직 운영 통합 경로와 KI-01~08 전체를 실행한 기록은 없다.

## 4. Provenance·Contradiction·Temporal Knowledge

### 근거와 신뢰

정답셋에 주장 → 파생 페이지/답변 → 원본 ID/버전/위치 → 독립 검증 결과의 계보를 지정한다. 인용 존재, 실제 지지 여부, 올바른 버전, 권한을 각각 채점한다. 단순 문자열 일치가 의미적 지지나 원본의 진실성을 보장하지 않는다.

계보 완전성은 원본까지 도달하고 필요한 조건·버전을 확인할 수 있는 주장 수 / 추적 대상 주장 수로 보고한다. 근거가 사라지거나 위조/순환된 인용, 검증되지 않은 추론은 확정 사실이 아니라 미확인/검토 필요로 남겨야 한다. 편집·승인 횟수는 신뢰 근거를 대신하지 않는다.

### 상충 탐지와 해소

정답 라벨은 같은 시점/조건의 실제 상충, 환경 차이, 시간적 대체, 근거 부족을 구분한다. 탐지 precision은 실제 상충으로 맞게 찾은 수 / 상충으로 표시한 수, recall은 맞게 찾은 수 / 정답 상충 수다. 분모가 0이면 해당 없음으로 표기한다. 오탐·미탐과 유형별 결과도 함께 보고한다.

해소는 탐지와 별도 채점한다. 충분한 근거가 있는 경우에만 조건부 결론과 변경 이유를 제시하고, 그렇지 않으면 보류·추가 검증으로 남기는 것이 정답이다. 최신 문서 우선이나 다수결로 모순을 숨기면 실패다. 자연어 모델 제안과 결정적 `key/context/value` 충돌 검사의 결과를 합산해 의미 성능으로 표시하지 않는다.

### 시간·맥락

사실의 유효 시작/종료, 시스템에 기록된 시각, 실제 검증 시각을 분리한 정답셋을 사용한다. 현재/과거/미래 시점 질문, 뒤늦은 정정, 같은 시점의 다른 환경, 유효 시점이 없는 자료를 포함한다. 시점·환경에 맞는 답변 수 / 해당 평가 답변 수와, 구식 권고·조건 누락·잘못된 확정의 건수를 기록한다. 시점을 알 수 없으면 한계를 밝혀야 한다.

## 5. 후속 에이전트 작업 성공률

**질문:** 축적한 지식을 실제로 사용하면 동일한 에이전트가 새로운 업무를 더 잘 수행하는가?

1. 정답 코드/문서와 실행 검증 기준이 있는 익명화 과제를 사전에 고정한다. 성공·실패 경험의 학습/정련용 과제와 평가용 홀드아웃을 분리한다. 평가 정답·성공 스크립트·해당 과제의 해결 결과가 위키에 유출되지 않도록 한다.
2. 동일 모델·프롬프트·도구·권한·시작 상태·토큰/시간 예산으로 위키 미사용/정적 위키/유지 위키 조건을 짝지어 비교한다. 허용된 원본 접근도 맞춘다. 실행 순서는 무작위/교차 배정하고 세션·캐시·파일 상태를 초기화한다.
3. 여러 과제와 반복 실행을 사용해 확률적 변동을 측정한다. 모든 조건에서 같은 객관적 완료·안전 기준을 독립 채점한다. 에이전트의 완료 선언이나 변경안 수용은 실제 성공이 아니다.
4. 성공률 = 검증된 성공 과제 수 / 사전 배정 과제 수. 동일 과제 쌍의 차이(percentage points), 과제 유형별 결과, 반복 간 분산과 신뢰구간/표본 수를 보고한다. 통계 방법과 표본 계획은 실행 전에 고정한다. 자료가 부족하면 개선 불확실로 판정한다.
5. 원본/위키 접근 로그와 사용한 지식 버전을 남기고 비용·지연·호출 수·유지 비용·안전 실패·근거 없는 확정을 함께 비교한다. 특정 과제나 실패를 사후 제외하지 않는다.
6. 평가 중 생성한 답변/성과는 평가 종료까지 학습 위키에 반영하지 않는다. 다음 라운드 개선에는 별도 학습 자료를 사용하고 새로운 홀드아웃을 유지한다.

통과는 사전 합의한 품질 개선, 비회귀, 안전 및 비용 조건을 모두 충족할 때만 선언한다. 실제 모델/도구 평가가 없으므로 현재 이 프로젝트가 에이전트 성능을 개선했다고 주장하지 않는다. CORE-010~012와 EVA-001~010의 검증 설계에 연결한다.

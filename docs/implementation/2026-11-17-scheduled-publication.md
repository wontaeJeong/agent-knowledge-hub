# 예약 발행 (Task 14 / REV-011)

## 목적과 불변식

사람이 검토·승인한 고정 변경 집합을 지정 시각에 발행한다. Ingest → 검토·발행 → Query의 발행 단계를 연결하며 North Star 불변식 5(검토 가능한 발전), 6(현재 권한), 8(실행 상태의 정직성)을 유지한다. 기존 지식·원본·기준 버전은 정본을 재사용한다. 문서 수나 에이전트 성능 개선은 주장하지 않으며 지식 효과는 EVALUATION의 대조 실험 대상이다.

## 실행 계약

- 웹의 변경 집합 카드에서 기기 시간대의 시각을 입력하고 미리보기에서 UTC, 현지 시각, 현재 실행 권한 만료와 예상 버전을 확인한다. 별도 `예약 확정`이 인간의 한 번의 발행 동의다. 승인 버튼·즉시 발행은 기존 계약을 유지한다.
- `POST /api/v1/changesets/:id/publication-schedules/preview`는 `{hash,dueAt}`의 엄격 DTO를 받는다. `dueAt`은 UTC ISO 시각이다. 현재 사람·현재 세션·기능 정책·정확한 승인 해시·원본 범위·검토 자격·정책·보호·메타데이터·기준 버전을 검사한다. 공통 `preparePublicationDb`의 읽기/도메인 계산만 수행하고 실제 발행은 하지 않는다. `previewHash`는 세션 식별자/내용/시각/권한 만료/현재 ACL·정책에 묶인 비교값이며 인증 토큰이 아니다.
- 같은 경로에 `POST`로 `{hash,dueAt,previewHash,confirm:"SCHEDULE_APPROVED_PUBLICATION"}`와 `Idempotency-Key`를 전달하면 검사 전체를 다시 수행하고 고정 동의를 저장한다. 승인되지 않았거나 이미 발행된 집합과 동시 대기 예약은 거부한다. 재전송은 같은 예약을 반환하며 다른 내용의 같은 키는 충돌한다.
- `GET /api/v1/changesets/:id/publication-schedules`는 자신의 최근 25개 상태를 반환한다. `GET /api/v1/publication-schedules/:id`, `POST /api/v1/publication-schedules/:id/cancel`은 예약 소유자인 현재 인증된 사람이 사용한다. 기능 생성이 비활성화돼도 조회/취소는 가능하다. 취소 권한에 새 발행 권한을 요구하지 않는다. 상태 조회 폴링은 유휴 세션을 연장하지 않는다.
- `scheduled_publications`는 일반 `durable_jobs`와 분리한 고정 인간 작업이다. 일반 에이전트 작업/서비스 자격증명은 승인·발행하지 못한다. 예약 행에는 해시된 세션 식별자만 보관하며 bearer/refresh/CSRF 비밀을 복사하지 않는다. 종료 시 세션 식별자도 지운다.
- App1의 기존 `OperationsLoop`가 15초 간격으로 최대 25개의 도래 예약을 검사한다. 별도 Pod·Redis·프로세스가 필요 없다. `OidcAuth.backgroundContext`가 네트워크 UserInfo/디렉터리를 DB 쓰기 잠금 밖에서 확인하고, 같은 세션·역할·현재 자격을 발행 트랜잭션 안에서 다시 확인한다. 서버 검증 issuer를 전달하여 기존 3역할 공간의 issuer 검증도 유지한다.
- 실행은 기존 `publish`와 공유하는 `preparePublicationDb`/`publishInTransaction`으로 현재 독립 검토자·작성자·해시·ACL 교집합·입력 계보·보호·필수 속성·메타데이터·기준 버전을 검사한다. 발행/중복 방지 영수증/예약 성공 상태는 같은 workspace 잠금 트랜잭션에서 커밋한다. 취소가 먼저 잠금을 얻으면 실행하지 않으며, 발행이 먼저 커밋하면 취소는 `SCHEDULE_FINISHED`를 반환한다.
- 실패한 발행 효과는 전체 트랜잭션을 롤백한다. 별도 트랜잭션에서 아직 `scheduled`인 행에만 안전한 오류 코드와 `failed`를 기록하여 경쟁하는 취소/성공을 덮지 않는다. 인프라 문제로 상태 기록까지 실패하면 예약은 대기 상태로 남고 스캐너가 오류를 보고한다. 실패를 성공으로 표시하지 않는다.
- 재시작에는 미커밋 효과가 남지 않고 기존 대기 행을 다시 읽는다. 중복 worker도 workspace/행 잠금과 정본 발행 영수증으로 중복 버전을 만들지 않는다. 종료 상태는 자동 재시도하지 않으며 현재 상태를 확인해 다시 검토·예약한다.

## 설정, 수명주기, 현재 제한

`scheduledPublication`은 기존 기능 정책의 한 항목이며 기본값은 true다. `AGENT_KNOWLEDGE_HUB_FEATURE_DEFAULTS={"scheduledPublication":false}`로 사이트에서 차단하거나 공간 정책 관리에서 비활성화할 수 있다. 미리보기/생성뿐 아니라 worker 실행 직전에도 현재 값을 검사한다. 비활성 상태의 기존 예약은 도래 시 `FEATURE_DISABLED` 실패로 기록하며 조회·취소는 유지한다.

예약은 세션 만료, 설정된 절대 만료, 현재 유휴 만료 중 가장 이른 시각 이전에만 가능하다. 장기간 예약을 보장하거나 세션을 갱신하지 않는다. 로그아웃·세션 철회·IdP 실패·유효기간 경과 시 재로그인과 새 동의가 필요하다. 약 15초 주기와 부하에 따른 지연이 있으므로 정각 실행 SLA가 아니다. 운영 전 별도의 장기 단일 작업 위임이 필요하다면 만료/철회/독립 검토 계약을 별도로 설계한다.

migration 128의 예약 테이블을 retention inventory에 명시 분류했다. 본문은 투영하지 않고 세션/요청 키/결과를 감추며 배치의 source/page ID 계보를 보존한다. 원본 → batch → 예약 관계를 따라 법정 삭제와 서명 복구 재생이 예약을 취소하고 세션·결과·사용자 요청 키를 지운다. 일반 unknown fail-safe와 법적 보존 검사를 완화하지 않는다. 예약 레코드 자동 보존기간 정리는 이번 범위에 추가하지 않는다.

## 검증과 한계

합성 원본·사람·로컬 OIDC/실제 PostgreSQL로 성공, 중복, 재시작, 취소 경쟁, 현재 해시/기준/정책/검토자/원본/보호/세션/기능 철회, 만료, 쓰기 실패 롤백, 삭제/복구 계보를 검증한다. 기존 정본 발행·버전·수명주기 회귀와 전체 프로젝트 검사를 실행한다. 화면 증거는 [별도 설명](../pr-assets/scheduled-publication/README.md)을 따른다. 사내 IdP·민감 자료·실제 배포·운영 SLA·모델 품질은 검증한 것으로 표시하지 않는다.

# 실행과 운영 전환

## 현재 로컬 데모

Node와 npm으로 실행한다. `npm ci` 후 `npm run dev`, 빌드는 `npm run build`다. `npm run preview`로 빌드 결과를 확인한다. 브라우저별 데이터이며 파일 DB나 서버 DB는 없다.

localStorage 키는 `agent-knowledge-hub.demo.v1`, 테마 키는 `agent-knowledge-hub.theme`다. 기존 이름의 브라우저 키는 새 키로 이전하며 새 키가 있으면 우선한다. 이전 쓰기가 실패하면 원본을 보존한다. JSON 내보내기는 데모 상태의 참고 사본이며 자동 가져오기나 서버 복원 기능은 없다. 초기화는 이전 키를 포함해 해당 브라우저의 데모 데이터를 삭제한다. 저장 용량 초과 시 쓰기는 오류로 알리며 완료 처리하지 않는다.

개발 서버는 0.0.0.0에 바인딩한다. 사내 민감 자료 없이 개인 검증용으로 사용하고 불필요한 네트워크 공개를 제한한다. 컨테이너는 정적 데모만 제공하며 동일하게 민감 자료 운영용이 아니다.

## 프로덕션 전에 필요한 운영 항목

| 항목 | 필수 결과 |
| --- | --- |
| 배포 | 고정 이미지·설정 검증·환경 분리·준비/생존 상태 |
| DB | 스키마 마이그레이션·접근 제어·삭제·버전 정합성 |
| 파일 | 원본·첨부 암호화·검증 다운로드·저장소 용량 관리 |
| 작업자 | 지속 작업 수락·임대·심박·재시도·중지·재처리함 |
| 관측 | 요청 ID·오류율·지연·권한 동기화·작업 지연·비용 |
| 백업 | DB·파일·키·설정·정책·삭제 기록의 일관된 복원 |
| 복구 | 실제 규모에서 RPO·RTO 실측과 다른 운영자의 복원 훈련 |
| 장애 | 모델 중단에도 읽기·일반 검색 유지, 잘못된 발행 중지 |
| 변경 | 단계 배포·프롬프트/모델 회귀·인덱스 안전 교체·복귀 |
| 조직 | 운영 담당·대체자·지원 시간·연락 경로·권한 인계 |

전체 조건은 OPS·JOB·NFR·SEC 요구사항에 있다. 초기에 제안한 SLO와 RPO/RTO는 실측 보장값이 아니다. 사내 규모·모델·지원 인력을 확정해 인수 기준으로 사용한다.

## 0.2 실행 경로

오프라인/모델 모드의 실행과 회사 CA 설정 경계는 MODEL_SETUP.md를 따른다. .env 변경은 Node 실행기 재시작 후 적용된다. Node는 dist가 있으면 우선 사용하고 배포 ZIP에서는 demo-dist를 사용한다. npm run dev와 nginx 컨테이너는 오프라인 UI 경로이며 모델 중계는 npm run demo가 제공한다. 브라우저 종료 후 자동 점검은 아직 없다.

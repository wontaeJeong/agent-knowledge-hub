# 1차 릴리즈 기반: 영속 발행 서비스와 사용량

**상태: 내부 서버 서비스/인증 어댑터 주입형 집계 API를 구현하고 로컬 PostgreSQL에서 검증했다. 1차 실사용 릴리즈 완료가 아니다.** 기본 앱과 `npm run demo`는 계속 브라우저 로컬 데모다. 업무 UI의 편입/발행/조회는 아직 서버 서비스로 전환하지 않았다. 사용량 화면만 같은 origin의 인증된 집계 API를 요청하며, 정적 데모에서는 명확한 미연결 상태를 표시한다.

## 목표와 제품 불변식

North Star의 원본 보존 → 여러 페이지 변경 제안 → 검토·발행 → 버전 고정 조회를 DB 트랜잭션으로 옮기는 첫 단위다. CORE-002~004, ACL-001~005·009, REV-004~006, VER-005, SEC-009, OPS-004 및 GOV-009·OPS-006의 일부에 대응한다. 서버 사용량은 운영 지표이며 지식 누적 품질이나 후속 에이전트 성능 향상의 증거가 아니다. 기존 수용 기준과 완료 상태를 변경하지 않는다.

## 구현 경계

| 파일 | 책임 |
| --- | --- |
| `server/migrations/` | workspace, 구성원, 자료별 독자, 원본, 페이지, 버전, 변경 집합, 승인, 발행·요청 영수증, 감사, 사용 이벤트 |
| `server/database.ts` | checksum 마이그레이션, 명시적 단일-client 트랜잭션, workspace 직렬화, 성공/실패 사용 기록 |
| `server/repository.ts` | 정본 로드/DB membership·ACL 검사. 정본 전체는 클라이언트에 반환하지 않음 |
| `server/service.ts`, `publication.ts` | 원본 등록, 고정/현재 버전 조회, 제안·승인·원자 발행, SHA-256 내용 및 승인 권한 스냅샷 검사 |
| `server/usage.ts`, `http.ts` | 주체별/검토자 전체 집계, 인증 콜백 필수인 GET 핸들러 |
| `src/features/UsageDashboard.tsx` | 집계 기준 → 핵심 수치 → 일별 그래프 → 작업별 표 → 미수집 모델 사용량 |

`KnowledgeService(pool)`의 메서드는 첫 인자로 `{ workspaceId, principalId }`를 받는다. **호스트 인증 어댑터가 검증한 신원만 전달해야 한다.** HTTP JSON, 사용자 이름, 브라우저 역할을 그대로 이 Context로 변환하면 안 된다. 독립 업무 REST/MCP 엔드포인트를 추가한 것이 아니며 업무 서비스의 HTTP 입력 검증/세션·CSRF는 후속 단위다.

- `registerSource(ctx, source, readers)`: workspace 구성원인 명시적 사용자 allowlist. 원본 ID 중복은 덮어쓰지 않고 거부한다. 원본의 작성자 확인/실행 증거 필드는 원본 주장이지 독립 검증이 아니다.
- `readPage(ctx, id, version?)`: 현재 page ACL과 선택 버전/현재 메타데이터의 source ACL을 모두 검사한다. 현재 제목을 반환하므로 현재 메타데이터를 읽을 수 없으면 과거 조회도 거부한다. 모든 과거 메타데이터 복원을 제공하는 것은 아니다.
- `propose(ctx, updates, sourceIds)`: 서버의 정본에서 기존 도메인 규칙을 재검사한다. 현재 경로는 `offline` 변경 제안이며 모델 호출을 수행하지 않는다.
- `approve(ctx, id, hash)`: 검토자만 승인한다. 내용·원본·기준·규칙과 관련 원본/페이지/연결 대상의 권한 스냅샷을 고정한다.
- `publish(ctx, id, hash, key)`: 현재 검토 권한, 원본 교집합, 연결 대상의 실효 접근권한과 승인 스냅샷을 재검사한다. 원본·기준·규칙·독자 집합 변경 시 전체 차단한다. 승인된 신규 페이지 독자는 원본 독자의 교집합이다. 기존 페이지 독자를 자동 확대/축소하지 않는다.
- 여러 페이지와 버전·승인 상태·발행 영수증·상태 변경 감사·성공 사용 이벤트는 한 트랜잭션이다. 키는 workspace/주체별, 발행 영수증은 workspace/집합별로 고유하다. 재시작 후 같은 DB에서 재호출해도 중복 버전을 만들지 않는다. 권한 검사는 replay에도 적용한다.

**동시성 계약:** 모든 서비스 변경은 workspace 행 `FOR UPDATE`로 직렬화한다. 향후 membership/ACL 변경 어댑터도 같은 workspace 잠금을 먼저 얻어야 한다. 서비스 외 임의 SQL 쓰기와 직접 DB 접근은 이 계약에 포함되지 않는다. 구성원/기존 ACL 행에도 공유 잠금을 사용한다. DB 계정/운영자 권한 격리와 직접 SQL 변경 감사는 배포 단계에서 별도 강제한다.

## 로컬 검증과 마이그레이션

Node.js 22.12 이상(검증: Node 24.22.2), Docker가 필요하다. 아래 자격증명/포트는 합성 시험 전용이며 실사용 배포에 재사용하지 않는다.

```sh
npm ci
docker compose -p akh-publication-test -f compose.test.yaml up -d --wait
export TEST_DATABASE_URL='postgres://knowledge_test:test-only-not-for-deployment@127.0.0.1:55439/knowledge_test'
npm run test:server
npm run check:server
DATABASE_URL="$TEST_DATABASE_URL" npm run db:migrate
```

시험은 고유 workspace fixture를 만들며 외부 DB에 자동 fallback하지 않는다. **폐기 가능한 시험 DB에서만 실행한다.** rollback 시험은 테이블 constraint를 일시 추가하므로 운영 DB/공유 개발 DB에서 실행하면 안 된다. 시험 compose는 localhost 포트와 tmpfs를 사용한다. 컨테이너 제거 시 시험 데이터는 사라진다.

실사용 DB URL은 서버 secret으로 공급하고 인증서 검증을 유지한다. `VITE_`에 넣지 않는다. migration은 advisory lock과 checksum으로 중복/변조를 검사하고 전체 rollback한다. 실행은 배포 전 단일 단계/Job으로 하며 앱 기동마다 실행하지 않는다. 실패하면 원인을 조사한 뒤 같은 버전을 재실행한다. 이미 적용한 SQL을 고치지 말고 새 migration을 추가한다. downgrade/파괴적 변경은 포함하지 않았다. 스키마 호환 배포/백업 복원은 출시 전 별도 검증한다. 이전 ACL 스냅샷 없는 승인은 발행할 수 없다.

## 사용 기록과 지표의 의미

- 감사: 원본 등록·제안·승인·실제 발행의 **상태 변경**. 실제 서버 주체 ID/리소스 ID/시각을 저장한다.
- 사용 이벤트: 위 서비스의 **모든 알려진 구성원 호출**. 페이지 조회와 성공/실패, 재시도 호출을 포함하며 workspace/주체 ID/작업/성공 여부/UTC 시각/서버 소요시간(ms)을 저장한다. 본문·질문·자격증명·원문 오류는 저장하지 않는다.
- 성공 이벤트 기록 실패 시 업무 트랜잭션도 rollback한다. 실패 호출은 rollback 후 별도 이벤트로 남긴다. 이 기록도 실패하면 `USAGE_UNAVAILABLE`을 반환한다. DB 연결 자체가 실패한 호출은 DB에 기록할 수 없으므로 외부 가용성 관측은 출시 전 별도 필요하다.
- `GET /api/v1/usage?days=7|30`: 일반 구성원은 본인, 검토자는 해당 workspace 전체 집계. 개별 사용자 명세는 응답에 노출하지 않는다. 본인 집계도 현재 membership가 필요하다. 캐시는 `private, no-store`, 인증은 호스트 콜백 필수이며 기본 허용 신원이 없다.
- 기간: 최근 7/30 **UTC 달력 날짜**, 시작일 00:00부터 조회 순간까지. 오늘은 부분 집계다. 전체/성공/실패 호출 수, 호출한 고유 주체 수, 실제 발행 수, 일별·작업별 분포, 평균 소요시간을 제공한다. 평균은 DB 연결 획득 후 대기/작업 시간을 포함하되 계측 INSERT/COMMIT 시간은 제외한다. 실패의 짧은 시간을 성능 개선으로 주장하지 않는다.
- 재시도는 호출 수에 포함된다. 실제 발행 수는 감사의 `batch.publish` 고유 발행을 센다. 활성 사용자는 계측된 호출의 고유 주체 수이며 방문자/로그인 사용자 수가 아니다.
- 현재 계측 범위는 위 내부 서비스뿐이다. **UI 페이지뷰·로컬 데모 업무 동작·Query/Lint 모델 호출·사용량 API 자체·미인증 요청은 계측하지 않는다.** 그룹 동기화/서비스 주체 분리/모델 공급자의 토큰·비용/파일 용량·전사 사용량은 미구현이다. 토큰/비용은 `null`(미수집)이지 0이 아니다.

프라이버시·보관 기간·삭제/비식별 정책·운영 조회 권한은 출시 전에 승인받고 구현한다. 현재 이벤트는 자동 정리하지 않으며 DB 운영자에게서 감사 데이터를 보호하는 불변 저장소도 아니다.

## UI와 검증 근거

사용량 메뉴는 `#/usage`다. 인증된 API를 같은 origin에 마운트해야 데이터를 읽는다. 호스트 어댑터는 세션/토큰을 실제로 검증하고 workspace를 서버에서 결정해야 한다. 정적 demo 서버나 브라우저 역할을 운영 인증으로 바꾸지 않았다.

[캡처 19개](pr-assets/server-usage/README.md)는 실제 로컬 DB 계측 응답 화면과 별도 UI fixture 상태를 구분한다. 측정 화면은 시험 workspace의 페이지 조회 15회(성공 12, 실패 3, 활성 주체 2) 응답을 브라우저에 주입한 것이다. DB→실제 HTTP 핸들러는 통합 시험으로 별도 검증했다. 운영 SSO/업무 UI 연결의 증거가 아니다.

| 측정 | 1440px | 390px |
| --- | --- | --- |
| 측정 화면 전체 높이 | 1576px | 1782px |
| 첫 집계 결론 상단 | 264px | 334px |
| 문서 가로 너비 | 1440px | 390px |
| 그래프 글자 | 14px | 14px |
| 표 헤더/본문 행 높이 | 46.5/47px | 46.5/47px |

새 화면이므로 동일 화면의 변경 전 수치는 없다. 초기 미연결 화면은 수정 전 알 수 없는 경로 fallback까지 중복 출력됐으나 브라우저 RED→GREEN으로 수정했다. 최종 미연결 높이는 1000/844px다. 긴 그래프보다 결론/수치를 먼저 배치하고 표는 600px 최소 너비/내부 스크롤을 사용한다. SVG 축소는 없으며 30일 그래프도 내부 스크롤이다. 기간 변경·재시도·라이트/다크·키보드 스크롤·모바일 탐색을 확인했다.

## 아직 남은 1차 릴리즈 게이트

최종 로컬 검증: Node 24.22.2/PostgreSQL 17.6에서 클라이언트 35개 + Node 6개 + 서버 26개 통과, 서버 타입 검사/251개 요구사항 검사/빌드/마이그레이션 재실행/diff 공백 검사 통과. 빌드의 기존 주 청크 크기 경고(511.15 kB)는 남아 있다. 서버 기반 PR 당시에는 토큰에 workflow 권한이 없어 CI 변경 푸시가 거부됐고 [적용용 패치](ci-server-tests.patch)를 남겼다. 이후 개발환경 PR #5에서 동일 PostgreSQL 서비스/서버 회귀를 독립 job과 최종 필수 게이트에 통합했다. 과거 패치는 기록용이며 현재 워크플로에 다시 적용하지 않는다. 실제 원격 실행 결과는 PR 검사/TESTING 기록을 따르며 운영 인수를 대신하지 않는다.

SSO/IdP·그룹 및 서비스 계정, 업무 API/MCP와 UI의 서버 전환, 권한 상속/철회 전파, 원본/첨부 오브젝트 저장소, 변경 집합 수정·반려·재검토 운영 흐름, Query/Lint/답변의 서버 영속화, 지속 작업/outbox/예산, 모델 품질/토큰·비용 계측, 사용 기록 보관 정책, 운영 감사 보호, K8s/TLS/환경 격리/관측/백업·복원/부하 검증이 남는다.

단순 대안을 선택해 workspace 전체 잠금/정본 hydrate를 사용했으므로 큰 workspace의 처리량은 미검증이다. 병목이 측정되면 행 단위 잠금과 필요한 개체만 로드하도록 바꾼다. 이 선택은 운영 최적화 유예이지 지식 품질·권한·릴리즈 기준 축소가 아니다. 실제 모델 종합/지식 누적 효과는 EVALUATION의 대조 평가 전까지 목표로 남는다.

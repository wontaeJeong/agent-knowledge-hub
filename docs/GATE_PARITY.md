# Gate ↔ Knowledge Hub 요구사항 양방향 비교 (2026-10-31)

본 변경은 공개 GitHub의 두 제품의 최신 \`main\`을 비교한 후, Gate의 협업 요구를 지식 공간 도메인에 맞춰 이식한 1차 기능 패리티다. **서로 다른 제품의 도메인 개체를 그대로 복사하지 않는다.**

| 공통 요구사항 | Knowledge Hub 현황 | 남은 운영 인수 |
| --- | --- | --- |
| Gate형 공지·내부 검토·VOC | \`/api/v1/board/posts\`, 공간별 ACL·검토자 전용 글/댓글·비공개 VOC·수정 버전·읽음 표시; \`#boards\` 운영 콘솔 | 실 SSO 그룹/철회와 보존 정책 |
| Gate형 7/14/30/90 조회 · CSV | 서버와 운영 콘솔·데모(명시된 합성 예시)에서 기간 선택, UTC 일별 0건 채움, 실측 호출 CSV 내보내기 | 메트릭 정확도/부하 |
| 역할별 콘솔·작업/검토 이력 | 기존 Organization/Team/Space 권한 및 운영 콘솔 유지 | 관리자·검토자 별도 현장 인수 |
| 제품 소개와 메모리·RAG 차별 | 기존 공개 랜딩·비교 화면 유지 | 내부 브랜딩·접근성 시험 |
| REST/MCP | 기존 세션 연동 및 권한 상한 유지 | 사내 실제 에이전트/IdP 확인 |
| STG/PROD | 기존 single-cluster 이중 namespace, 이미지 digest·migration·NetworkPolicy 가드 | 실제 secret·DNS·CNI·백업 복구 확인 |
| 모델 공급자·토큰·비용 | 현재 OpenAI 호환 호출, 토큰/비용은 미계측(\`null\`) | Bedrock/SystemOne 어댑터, 온프렘 모델 사용량 계측 구현 필요 |
| 범위 API 키·Device Code | 운영 콘솔의 합성 관리 화면만 존재 (실제 발급 API 미구현) | 조직 SSO 수명주기·철회·scope 모델 확정 후 별도 구현 필요 |

## 보안 계약

- 공개 게시글은 현재 workspace의 유효한 회원만 열람한다. 내부 검토 글과 내부 댓글은 현재 reviewer만, private VOC는 게시자만 볼 수 있다. 화면의 사용자 역할은 서버 권한 결정을 대신하지 않는다.
- 게시물 작성/댓글/수정/읽음 기록은 인증 세션 유효성을 트랜잭션에서 다시 확인한다. 누락·철회된 멤버는 실패하고, 수정은 revision 충돌을 거부한다.
- Markdown은 본문 데이터로 보존하지만 게시글을 실행 가능한 HTML로 렌더링하지 않는다. 업로드·외부 URL 실행 경로는 없다.
- 자동 테스트는 도메인 회귀이지 사내 실제 SSO·데이터 등급 인수가 아니다.
- 데이터베이스 migration \`008-boards.sql\`은 서버 시작에 자동 적용되지 않는다. 이전 절차처럼 별도의 Job 성공 후 앱을 올린다.

## 후속 우선순위

1. 사내 SSO 계정의 만료/정지/그룹 철회에 즉시 연결되는 범위 API 키 및 8자리·10분 Device Code 인증, 1회 비밀 노출과 상세 사용 이력.
2. On-prem·Bedrock·SystemOne 공급자별 추론 계측(입력/출력/캐시 토큰, latency, 미보고 비용은 null), 모델 정책별 감사/CSV.
3. 공지/VOC 알림·첨부·읽음 지표, 보존/삭제 감사 및 실제 사내 인수.
4. 멀티 인스턴스 대비 안전 큐·외부 Blob·백업 일관성 및 3만 명 규모 성능 인수.

완료를 주장하는 범위는 코드에 구현한 항목만 해당한다. 각 추가 요구사항은 보안 모델·테스트·운영 인수와 함께 진행한다.

# 보안 경계

후속 서버 경로는 `server/runtime/`의 OIDC/JWKS·DB 세션·CSRF·현재 membership/원본·페이지 ACL·전체 모델 입력 계보 검사를 제공한다. 개발 Keycloak/kind의 실제 회귀와 사내 보안 인수는 구분하며, 아래 브라우저 데모 경고는 `/?demo=1`과 정적 실행기에 계속 적용한다. 현재 변경 범위/독립 리뷰/남은 운영 통제는 [인계](AGENT_HANDOFF.md) 및 [운영 설정](OPERATIONAL_SETUP.md)을 따른다. 실제 사내 인증/자료 등급/파일 저장/감사 보호/삭제·백업·네트워크 정책의 미충족 조건을 해소하기 전 민감 자료 운영을 승인하지 않는다.

이 배포물은 개인 브라우저에서 합성 데이터로 사용한다. 실제 사내 인증·기밀정보·다중 사용자 운영은 지원하지 않는다.

현재 역할 선택과 공개 범위 필터는 UX 및 도메인 규칙의 시연이다. 모든 데모 상태가 클라이언트에 있으므로 서버 보안과 동일하게 취급하면 안 된다. 공유 토큰도 같은 브라우저 안의 동작 시연이며 암호화된 서버 공유가 아니다. 감사 기록은 사용자가 수정할 수 있는 localStorage 데이터다.

Markdown은 DOMPurify로 정제해 렌더링하고 외부 HTML 원문 실행을 의도하지 않는다. 이 통제만으로 인젝션이나 콘텐츠 보안을 전부 해결했다고 간주하지 않는다. 모델 키·프록시 자격증명을 VITE_ 변수에 넣지 않는다. 실제 공급자 키는 서버 비밀 저장소에서 관리해야 한다.

## 서버 구현의 불변식

- 사용자·그룹·서비스 주체와 공유 범위를 서버에서 확인한다.
- 원본에서 파생된 모든 지식은 원본 권한의 교집합을 기본으로 따른다.
- 열람·검색·답변·첨부·과거 버전·내보내기·캐시마다 현재 권한을 적용한다.
- 원본 및 권한 동기화가 오래되면 제한 모드로 전환한다.
- 근거 문서의 지시문이 정책이나 도구 권한을 바꾸지 못하게 한다.
- 파일 변환·URL 수집은 격리하고 SSRF·XSS·경로 탈출을 검사한다.
- 공유 확대·공식 기준 변경·삭제는 정한 권한과 검토 절차로 처리한다.
- 복원은 현재 접근 제한과 삭제 기록을 유지한다.

배포·보안·AI 시험은 원래 35개 인수 시나리오 및 현재 도메인 테스트와 구분해 기록한다. 민감 자료 수집 전에 회사 정책과 실제 권한 검증을 완료한다.

## 0.2 모델 중계 경계

Node 실행기의 /api/model은 localhost Host·브라우저 Origin·JSON·요청 크기·서버 환경의 URL과 키를 사용한다. 자격증명은 VITE_나 응답에 넣지 않는다. 실제 모델 결과도 원본 범위·스키마·정확한 인용과 발행 검사를 통과해야 한다. 이 로컬 통제는 사내 SSO·사용자별 서버 ACL·토큰 위임·감사 보호를 구현한 것이 아니다. 원본·위키 본문의 지시문은 정책 데이터로 취급한다.

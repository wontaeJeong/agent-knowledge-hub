# 실제 모델 연결과 로컬 데모

Node.js 22.12 이상이 필요하다. 실행본을 담은 압축본은 의존성 설치 없이 `npm run demo`로 연다. Git 소스로 가져왔다면 `npm ci`, `npm run build`, `npm run demo` 순서로 실행한다. 새 빌드 dist가 있으면 demo-dist보다 우선한다.

## 오프라인

http://127.0.0.1:8080/#/compile 에서 시작한다. 모델 키가 필요 없다. 자료 편입은 명시된 지식 제목·사실 구조, 질문은 검색 발췌, Weekly는 실제 구조 검사다. 화면의 예시 자료도 직접 수정할 수 있다. 질문은 발행본만 사용하므로 먼저 승인·발행해야 한다.

## 모델 서버

1. .env.example을 .env로 복사한다.
2. AGENT_KNOWLEDGE_HUB_LLM_BASE_URL에 사내 OpenAI 호환 서버의 /v1까지 지정한다. 예: http://127.0.0.1:4000/v1. 실제 요청은 /chat/completions에 보낸다.
3. AGENT_KNOWLEDGE_HUB_LLM_MODEL과 필요한 경우 AGENT_KNOWLEDGE_HUB_LLM_API_KEY를 서버 환경에 지정한다. 기존 설정은 .env.example의 새 변수명으로 변경한다.
4. `npm run demo`를 재시작하고 브라우저를 새로고침한다. 실행 엔진에서 연결된 모델을 선택한다.

서버가 wiki/SCHEMA.md와 작업별 출력 계약을 system 메시지에 넣는다. 선택한 원본과 같은 공유 범위의 발행본을 해당 모델로 전송한다. 질문은 현재 검색된 최대 4개 발행본을 전달한다. 서버 키는 응답·클라이언트 번들에 넣지 않는다. 회사 프록시·CA는 회사 표준 Node 설정을 사용하고 TLS 검증을 끄지 않는다.

입력 500KB, 편입 문서 최대 40개·변경 최대 20개, 요청 60초, 출력 max_tokens 6000의 데모 상한이 있다. 모델은 JSON 형식의 답변을 지원해야 한다. 잘못된 스키마·원본에 없는 사실 인용·위키에 없는 답변 인용·범위 확대는 반영하지 않는다. 연결 실패를 오프라인 성공으로 대체하지 않는다. 클라이언트 입력이 신뢰되는 것은 아니며 서버 인가·DB 검증은 프로덕션 전환에서 다시 구현한다.

`npm run dev`와 nginx Docker 구성은 오프라인 UI 개발·정적 시연 경로다. 모델 연결 검증은 `npm run build` 후 Node의 `npm run demo` 경로에서 수행한다. 모델 키를 VITE_ 환경변수로 넣거나 빌드에 포함하지 않는다.

## 검증 범위

테스트의 로컬 가짜 OpenAI 호환 서버로 정책·요청 전달·JSON 오류·업스트림 실패·키 비노출을 검사한다. 이는 실제 사내 모델의 품질·GPU·프록시·CA·인증 호환성을 검증한 결과가 아니다. 해당 모델에 연결한 뒤 익명화한 업무 평가셋으로 종합 품질과 오류 누적을 평가해야 한다.

이 실행기는 localhost에만 바인딩한다. SSO·서버 ACL·지속 DB·감사 보호·무인 스케줄러가 없으므로 사내 운영 서버로 노출하지 않는다. 실제 사내 자료를 사용하기 전 전체 요구사항의 출시 게이트를 충족한다.

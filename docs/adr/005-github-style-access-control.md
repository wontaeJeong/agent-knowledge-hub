# ADR 005 (제안): 소유권·공개 범위·공간 역할을 분리한다

- 날짜: 2026-10-30
- 상태: **핵심 구현 포함 / 확장 계약 제안 유지** — Organization·Team·공간 5역할·초대·Owner·지정 검토자·명시적 이관을 구현했다. 범위 토큰/서비스 주체·Company·문서 한정 공유 등은 [구현 가이드](../IMPLEMENTATION_GUIDE.md)의 후속 범위를 따른다. 운영 인수 완료는 아니다.
- 대상: 로컬/개인/팀 공유, 서버 인증·권한, 개인 커넥터와 API/MCP의 공통 접근 계약
- 상세: [권한 모델과 수용 시나리오](../ACCESS_CONTROL.md)
- 상위 기준: [North Star](../LLM_WIKI_CORE.md), [ADR 002](002-persistent-wiki-loop.md), [ADR 004 제안](004-unified-knowledge-service.md)

## 배경

최신 `main@ec148ef9`는 실제 OIDC·DB 세션, `reader/editor/reviewer` workspace 역할, 원본/페이지 allowlist, 전체 모델 입력 계보와 승인 ACL 검사를 제공한다. 로컬 개인 위키 커넥터는 아직 합성 서비스의 별도 경로다. 현재 역할만으로 개인 소유·팀 멤버십·그룹별 공간 접근·관리와 검토의 분리를 표현하기 어렵다.

사용자는 기존 로컬/개인/팀(공유) 컨셉에 GitHub와 유사한 권한을 추가하도록 요청했다. 로컬 저장 위치, 소유권, 공개 범위, 편집·검토·관리 권한을 한 단계의 등급으로 만들면 개인 초안이 의도 없이 공유되거나 원본 제한이 약해질 수 있다.

## 제안하는 결정

1. **사용자/팀 네임스페이스 → 지식 공간 → 사용자/접근 그룹 역할**을 둔다. 기존 `workspaces`는 지식 공간으로 유지하며 조직 ID로 재해석하지 않는다.
2. **Read/Triage/Write/Maintain/Admin**의 공간별 역할을 사용한다. 팀 Owner/Member와 시스템 운영자는 별도 관계다. 팀 기본 권한은 none, 새 공간은 Private다.
3. **Private/Team/Company는 기본 발행본 독자만 정한다.** 개인은 본인 전용, 팀은 명시 권한/팀 독자, 전사는 허용된 사내 디렉터리 독자다. 공식성·편집 권한·로컬 반출과 구별한다.
4. **공간 역할 ∩ 현재 자료/전체 입력 계보 ∩ 위임 상한 ∩ 작업 정책**을 적용한다. 높은 역할·복사·정제 주장으로 원본 제한을 우회하지 않는다. ACL-006의 정제본 공개 결정은 별도 권한/기록이 필요하다.
5. **개인 파생본 → 선택 revision 변경 제안 → 독립 지정 인간 검토 → 원자 발행**을 기본으로 한다. 자기 승인·서비스 주체 승인·관리자 보호 우회를 허용하지 않는다. 팀에 독립 검토자가 없으면 발행을 기다린다.
6. **웹/REST/MCP/동기화/작업자는 같은 서버 정책**을 따른다. 토큰은 현재 주체 권한과 발급 상한의 교집합이며 첫 구현의 위임 경로에는 승인·발행·권한 관리 권한을 주지 않는다.
7. **신원과 제품 권한을 분리한다.** OIDC 그룹→단일 역할의 현행 갱신을 공간 바인딩으로 전환하고 회수한 권한의 재로그인 자동 복구를 막는다. 기존 reviewer는 Admin/팀 Owner로 자동 승격하지 않는다.

## 영향과 트레이드오프

- Ingest/Query/Lint·질문 재편입·근거 파생본에 같은 접근 규칙을 적용해 North Star의 근거·현재 권한·검토 불변식을 구체화한다. 제품 목표나 런타임 `wiki/SCHEMA.md`의 의미는 바꾸지 않는다.
- 공간 역할만 쓰는 모델보다 자료 제한·독자 교집합 계산과 UI 설명이 복잡하다. 대신 제한 원본을 통한 지식 누출을 차단한다. 초기에는 같은 PostgreSQL 서비스/트랜잭션을 확장하고 외부 정책 엔진은 필수로 도입하지 않는다.
- 승인 후 관련 멤버십·역할/ACL 변경은 보수적으로 재검토한다. 팀 규모가 커져 재검토 빈도가 병목이 되면 실제 측정 후 영향 범위를 최적화하며 안전 조건은 유지한다.
- 로컬 연결 중 동기화·미전송 보존·재연결 재개를 유지한다. 상시 로컬 프로세스와 보호 캐시의 완전 오프라인 열람은 도입하지 않는다. 이미 반출된 평문의 완전 회수도 보장하지 않는다.
- 개인 소유권 유지와 팀 책임을 위해 첫 구현의 개인 공간은 본인 전용이다. 공동 작업은 팀 공간에서 한다. 외부 Guest/익명 Public/소지자 링크는 기존 선택 기능으로 기본 비활성 상태를 유지한다.

## 대안

| 대안 | 채택하지 않는 이유 |
| --- | --- |
| 전사 단일 reader/editor/reviewer/admin | 다른 공간 편집 권한의 전파, 검토/관리 혼동, 팀 소유권 부재 |
| 모든 문서에 개별 사용자 ACL만 부여 | 팀/그룹 변경과 실효 권한 설명이 어렵고 반복 관리가 커짐 |
| GitHub 역할/공개 모델 그대로 적용 | 원본 파생 제한·공식성·반출·독립 사람 검토라는 지식 제품 계약을 충분히 표현하지 못함 |

## 구현·검증과 결정 범위

[ACCESS_CONTROL.md](../ACCESS_CONTROL.md)의 데이터 모델·호환 마이그레이션·UX·AC-01~24를 후속 작업 기준으로 제안한다. AC는 기존 251개 요구사항과 35개 인수 시나리오를 대체하지 않으며 의미 품질·사내 운영 수용 전체를 통과한 것은 아니다. 핵심 권한/HTTP/OIDC 철회 회귀는 실제 구현과 함께 추가했다. 역할/ACL/토큰/원본 철회·OIDC 재로그인·발행 경쟁을 실제 서비스 경로에서 검증하기 전 구현 완료로 표시하지 않는다. 의미 품질/업무 성과는 별도 [평가 계약](../EVALUATION.md)을 따른다.

이 ADR은 설계 리뷰 대상이며 기존 ADR 004를 자동 채택하거나 운영 정책을 승인하지 않는다. 병합된 설계 문서와 배포된 접근 통제를 구별한다. 이후 결정이 바뀌면 이 ADR의 상태·상세 계약·연결 문서·이관 계획을 함께 갱신한다.

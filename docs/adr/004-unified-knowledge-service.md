# ADR 004 (제안): 로컬 위키와 LLM Wiki를 단일 지식 서비스로 수렴한다

- 날짜: 2026-10-29
- 상태: **제안(Proposed)** — 이 PR은 설계 검토 요청이며 채택·구현·운영 검증을 뜻하지 않는다.
- 대상: 개인 로컬 위키와 웹 Ingest → Query → Lint의 미래 통합 경계
- 상위 원칙: [North Star](../LLM_WIKI_CORE.md), [ADR 002](002-persistent-wiki-loop.md), [초기 배포 설계](003-single-cluster-initial-release.md)

## 배경

현재는 **두 개의 분리된 개발 경로**가 있다.

1. \`src/domain/wiki.ts\`와 웹 데모: 원본 스냅샷, 여러 페이지 변경 집합, 승인·발행, 발행본 질의, 질문 재편입, 명시 사실 Lint를 로컬에서 시연한다. 제품 서버 ACL·DB 트랜잭션·지속 작업은 없다.
2. \`scripts/wiki-connector/\`와 STDIO MCP: 허용된 최신 페이지 텍스트/참조를 개인 JSON 작업본에 복제해 연결 중 동기화하고, 충돌을 보존하며, **단일 페이지** 공유 변경을 제안한다. 합성 loopback 서비스이며 원본 편입·지식 종합·재편입·Lint와 통합되지 않았다.

이를 두 개의 독립된 지식 정본으로 키우면 공유 발행과 지식 편입의 의미, 근거·권한·버전 규칙이 갈라질 수 있다. **동기화 성공은 지식 발전의 증거가 아니다.**

## 제안하는 결정

**서버의 공통 지식 도메인 서비스를 권한·지식·발행의 최종 정본으로 두고, 로컬 커넥터는 허용된 범위의 개인 작업본/조회 캐시/변경 제안 어댑터로 사용한다.** 웹·MCP·향후 매니저는 같은 검증·발행 규칙을 사용한다.

- **Raw Sources:** 출처·버전·원문 위치·수집 권한·정정/철회 상태는 서버가 검증한다. 로컬 \`sourceRefs\`는 *참조*이지 원본의 진위·공유 허가를 증명하지 않는다.
- **Knowledge:** 주제·개념·연결·조건·주장·계보를 서버가 검증한다. 서로 의존하는 변경은 원자적 변경 집합으로 발행한다.
- **Local Draft:** 사용자가 허용받은 지식의 복사·개인 파생본을 유지한다. \`wiki_write\`/ \`wiki_sync\`를 공유 발행이나 지식 검증으로 간주하지 않는다.
- **Proposal:** 개인본의 선택 revision과 공유 기준을 고정하고 원본 권한, 관련 페이지, 승인한 스냅샷과 정책 버전을 발행 직전에 다시 검증한다.
- **Feedback:** 인용·실제 실행 결과와 검증 근거는 재검토 후보가 된다. 에이전트 주장만으로 공식 사실을 추가하거나 파생 답변을 독립 증거로 세지 않는다.
- **Permission:** 조회 권한과 로컬 복사 허용은 별개다. 과거 버전·검색·충돌·파생 지식까지 현재 권한을 적용한다. 권한 확인이 안 되면 보호된 캐시는 제공하지 않되, 이미 반출한 평문의 완전 회수는 약속하지 않는다.

## 책임 경계

| 항목 | 서버/검토 책임 | 로컬/에이전트 역할 |
| --- | --- | --- |
| 원본 등록·정정·철회 | 권한과 원본 증거 확인 | 허용된 ID/버전/위치 참조 및 등록 제안 |
| 발행 지식과 근거 계보 | 권한·조건·원본 연결 검증 | 조회·개인 작업본 수정 |
| 검토·의존 페이지 발행 | 기준/승인 해시 재검사, DB 원자 발행 | 변경 후보와 이유 제안 |
| 개인 작업·기기 충돌 | 개인 동기화 정책 | draft·충돌·병합안 보존 |
| 실행 결과·교훈 | 독립 검증, 검토·발행 | 사용한 지식 버전/관측/증거 제출 |

**현재 코드는 이 목표 계약을 충족하지 않는다.** 특히 현행 단일 페이지 제안을 복수 페이지 지식 컴파일의 운영 계약으로 자동 승격하지 않는다.

## 검토한 대안

1. **로컬 커넥터를 정본으로 사용 — 반대 제안:** JSON 동기화만으로 원본 권위·원자 발행·조직 권한을 보장할 수 없다.
2. **웹 엔진과 로컬 엔진의 영구 분리 — 반대 제안:** 검증·버전·계보 로직 중복 및 불일치 위험이 크다.
3. **로컬 작업본을 제거하고 원격만 사용 — 반대 제안:** 개인 작업·연결 중 적은 본문 전송·기기 간 편집 목표를 잃는다.

## 범위와 채택 조건

최종 DTO/DB 스키마, API·MCP 도구 이름, 공간 계층, 자연어 자동 병합/발행은 확정하지 않는다. 이 ADR을 **채택**하려면 제품 책임자의 리뷰 후 상태를 별도 변경한다. 단순 문서 병합을 운영 승인 또는 통합 완료로 표시하지 않는다.

단계와 반증 가능한 수용 시나리오는 [통합 계획](../KNOWLEDGE_INTEGRATION.md), 평가 근거는 [EVALUATION](../EVALUATION.md)에 있다. 기존 251개 요구사항과 Ingest → Query → Lint는 유지한다.

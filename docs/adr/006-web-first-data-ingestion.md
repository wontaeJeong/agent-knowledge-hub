# ADR 006: 웹 데이터 입력과 MCP를 공통 비동기 편입 서비스로 연결한다

- 날짜: 2026-10-30
- 상태: **구현 포함 / 운영 인수 별도** — 웹/파일 파서/영속 worker/개인 정리/원본 공개 검토/공유 발행 경로를 구현했다. 실제 범위는 [구현 가이드](../IMPLEMENTATION_GUIDE.md)를 따른다.
- 상세: [데이터 편입](../DATA_INGESTION.md), [대화 기록 계약](../CONVERSATION_IMPORT.md)
- 관련: [North Star](../LLM_WIKI_CORE.md), [ADR 002](002-persistent-wiki-loop.md), [ADR 004 제안](004-unified-knowledge-service.md), [ADR 005 제안](005-github-style-access-control.md)

## 배경과 현재 격차

사용자는 MCP 외에도 데이터를 직접 넣으면 자동으로 정리해 위키에 반영하는 기능을 원하며, 대표 사례로 메신저 대화 1주일치 업로드와 데스크톱 앱 필요 여부를 제시했다. 기존 COL-002/005/012/013·JOB 요구사항은 이 수동 입력·선택 수집·변환·지속 작업을 이미 제품 범위에 포함한다.

변경 전 운영 경로는 본문 100,000자의 원본 JSON과 원본 ID 최대 20개의 ingest를 받았다. 실제 OIDC/DB/모델·changeset/원자 발행은 있었으나 파일 업로드·형식별 대화 파서·재개·영속 worker/lease·입력 UX가 없었다. 이번 구현은 별도 개인 편입 경로와 영속 상태를 추가한다. 기존 `runtime_jobs`의 동기 시도 기록과 새 편입 큐를 구별한다.

## 결정

1. **웹을 기본 입력 화면**으로 제공한다. 붙여넣기/파일 선택/드래그앤드롭 후 형식·기간·포함/제외·등급·목적지 확인만으로 정리할 수 있게 하고 앱 설치·MCP·페이지 ID 입력을 요구하지 않는다.
2. **웹·REST·MCP·추후 승인 커넥터가 같은 접수/편입/지식 서비스**를 사용한다. 원본/정규화/후보/공유 발행을 분리하고 기존 Ingest → Query → Lint·근거/권한·검토 서비스를 확장한다.
3. **자동 처리의 기본 종료는 검토 가능한 변경 집합**이다. 자동 형식 처리·분류·종합과 독립 사람 검토·공유 발행을 구별한다. 이전 원본과 기존 위키를 비교해 조건/결론/관계를 갱신하며 요약 파일 증가로 완료를 대신하지 않는다.
4. **서버에 원본·manifest·영속 실행/단계·ExecutionGrant·lease/fencing을 둔다.** 업로드 완료/실행 수락 뒤 탭을 닫아도 계속하고, 원본/역할 철회·명시적 로그아웃·grant 만료 시 제한한다. 브라우저 worker/PWA나 공용 관리자 키로 지속 작업을 대체하지 않는다.
5. **대화는 근거를 가진 원본**으로 처리한다. 스레드·시간·수정/삭제·중복·화자 신원/접근 증거·제안/결정/완료 주장을 구별하고 긴 문맥의 누락/상충을 보고한다. 첨부 링크나 완료 발언을 실제 독립 증거로 승격하지 않는다.
6. **데스크톱은 첫 필수 구성으로 만들지 않는다.** 승인된 로컬 전처리/OS 연동이 실제로 필요하면 기존 연결 중 브리지 또는 별도 클라이언트를 ADR로 검토한다. 상시 로컬 daemon 제외 결정과 서버 원본/권한 정본을 유지한다.

## 대안과 트레이드오프

| 대안 | 판단 |
| --- | --- |
| 처음부터 전용 데스크톱 앱 | 수동 파일 입력에는 필수 아님. 배포/업데이트/서명·OS 지원 부담이 늘며 서비스 권한을 해결하지 못함 |
| 웹에서 모든 LLM 처리/상태를 유지 | 탭/프로세스 종료·모델 키·영속 복구/공유 원자성에 불리함. 브라우저는 입력 미리보기/UI, 서버는 실행 정본 |
| MCP만 제공 | 일반 사용자의 직접 입력·검토 UX와 기존 COL-002를 충족하지 못함 |
| 업로드마다 요약 문서를 자동 발행 | 기존 지식/근거/상충·개인/팀 공개 경계와 검토 불변식을 충족하지 못함 |
| 새 브로커/벡터 DB/대규모 worker 플랫폼부터 도입 | 초기 App1/DB1 목표에서 필수 아님. PostgreSQL 지속 작업과 제한된 bytea 원본 조각으로 시작하고 실측 후 객체 저장소/worker를 분리 |

제한된 PostgreSQL 원본 조각·영속 worker·adapter/coverage·실행 grant로 구현 복잡도가 늘어난다. 대신 브라우저 수명과 독립된 재개, 권한 회수, 중복/정정·근거 검토를 같은 계약으로 유지한다. 모델 외부 재시도/과금까지 exactly-once를 보장하지 않는다. 첫 대화 어댑터 밖 형식은 명시적으로 지원 대기이며 파일 처리의 기존 필수 요구사항을 삭제하지 않는다.

## 구현과 검증의 범위

원본 등록→웹 미리보기/선택→지속 처리→기존 위키 변경 집합→사람 검토/발행→인용 Query/Lint의 수직 경로를 구현했다. DATA_INGESTION의 DI-01~24, 대화 정답셋·의미 품질/비용 대조, 기존 권한·발행·복구 인수를 실행해야 한다. 순수 파서/모델 계약·DB·실제 HTTP/SDK MCP·브라우저 fixture 회귀를 추가했다. 실제 LLM 의미 품질·사내 원본 호환·운영 복원/부하 수용 결과는 아직 별도다.

기존 251개 요구사항·35개 인수 시나리오, ADR 004와 ADR 005의 남은 확장 계약, North Star·런타임 규칙의 의미를 바꾸지 않는다. 이 ADR을 문서로 병합해도 새 제품 지원 형식·배포 기능·운영 승인으로 자동 승격하지 않는다. 현재 구현 한계와 실행 증거는 [인계](../AGENT_HANDOFF.md)를 따른다.

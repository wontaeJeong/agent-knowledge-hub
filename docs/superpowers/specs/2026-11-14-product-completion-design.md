# 운영 고도화를 제외한 추가 기능 완성 설계

작성일: 2026-11-14. 기준: `main@92bd63c`. 상태: **사용자 승인, 구현 진행**. 사용자는 설계 제시 후 “진행해”로 승인했다.

## 요청과 범위

사용자 요청은 운영 고도화를 제외한 나머지 추가 기능을 구현하고, 기능별 PR을 열어두는 것이다. 이번 요청에는 머지가 포함되지 않는다. 이미 머지된 PR #31의 [현재 현황](../../CURRENT_STATUS.md), [정비 기준](../../requirements/MAINTENANCE.md)과 기존 기능 계약을 구현 근거로 삼는다.

범위에는 해석이 두 가지 있다. 이 문서는 우선 **현재 현황 문서에서 확인한 잔여 제품 기능 전체**를 대상으로 작성했다. 사용자의 진행 승인에 따라 이 10개 잔여 기능을 구현한다. 원래 요구사항의 확장·선택 항목 전체를 새로 추가하는 범위 확대는 하지 않는다. 실시간 공동 편집, 수식/다이어그램, 일괄 편집, 외부 게스트·익명 링크, 추가 도구/외부 서비스 연동 등을 임의로 삭제하거나 이번 범위에서 완료로 표시하지 않는다.

배포·HA/증설·부하/SLO·관측/운영 알림·독립 백업/재해 복구·인증서 교체·사내 인수 절차의 고도화는 제외한다. 기능을 안전하게 쓸 수 있도록 하는 현재 ACL, 원본 상한, 검토, 멱등성, 작업 재시도, 사용자 데이터 삭제/철회는 포함한다. 기능이 사용하는 기존 서버 작업 큐의 연결도 포함한다. 운영 배포를 수행하거나 실제 회사 자료·계정 정책을 변경하지 않는다.

제품 목표·251개 요구사항·필수 236개 수용 기준·North Star·런타임 규칙은 보존한다. 운영 고도화를 이번 작업에서 제외하는 것은 실서비스 출시 게이트를 면제하는 결정이 아니다.

## 접근 방식

기존 TypeScript/PostgreSQL 서비스와 React 화면을 재사용해 **사용자가 완료할 수 있는 업무 흐름별 PR**로 연결한다. 독립 서비스만 추가하거나 HTTP의 `503`만 제거한 상태는 완료가 아니다. 서비스, 인증된 HTTP, 필요한 API/MCP, UI, 회귀 시험, 현재 현황/인계를 해당 기능 PR에 함께 포함한다.

API부터 모두 연결한 뒤 UI를 한꺼번에 연결하는 방식도 가능하지만, 이미 독립 UI와 서비스가 존재하고 기능별 PR이 요청되었으므로 각 PR의 기능 동작을 검토하기 어렵게 만든다. 별도 서비스나 새 저장소를 만드는 방식은 현재 공통 검증·발행 경계를 다시 구현해야 하므로 사용하지 않는다. 이는 작성자의 구현 제안이며 새로운 제품 정책 승인으로 간주하지 않는다.

변경은 각기 격리된 worktree/브랜치에서 진행한다. 독립 기능은 `main`을 대상으로 하고, 선행 코드가 필요한 후속 PR은 선행 기능 브랜치를 base로 명시한다. 각 PR 본문에는 의존 PR, 독립 변경 범위, 검증 결과와 머지 순서를 표시한다. 사용자 요청 없이 머지하거나 자동 머지를 예약하지 않는다.

현재 열린 [PR #30](https://github.com/wontaeJeong/agent-knowledge-hub/pull/30)은 지식 탐색·트렌딩을 다룬다. 해당 기능과 migration 110을 중복 작성하지 않고, 이번 기능 변경과의 충돌을 확인한다. 이 PR의 기존 화면 증거 미충족을 새 기능 구현으로 해결했다고 표시하지 않는다.

## 기능별 PR 단위

다음 번호는 구현 순서의 초안이며 요구사항 ID가 아니다. 공유 파일 충돌 때문에 기능들을 하나의 대형 PR로 합치지 않는다.

### P1. 개인 후속 대화

- 관련: QNA-005/008/009, SRH-002/004, CORE-005.
- 기존: `server/questions/service.ts`, `http.ts`, `INTEGRATION.md`, `src/operational/questions.tsx`. runtime HTTP는 상세와 턴 실행을 차단하고 있다.
- `QuestionsService`의 `TrustedQuestionContext.resolve/onCreated`와 runtime의 다른 trusted context 형태를 실제 조회/전송/저장 경로에서 통합한다. 브라우저가 전달한 과거 메시지나 seal을 신뢰하지 않는다.
- `createRuntimeJobs`에 question adapter를 연결하고 같은 service 인스턴스를 HTTP에서 사용한다. 수락한 턴은 실제 durable receipt를 반환한다. 큐가 없는 호스트는 명확하게 비활성으로 남는다.
- 이력은 본인에게만 보이며, 원본/페이지 권한이 철회되면 다음 모델 요청에서 그 이력의 내용을 제외한다. 수락 후 입력이 바뀌면 오래된 입력으로 실행하지 않는다. 답변과 완료 턴은 같은 fenced transaction에서 저장한다.
- 앱에 기존 QuestionsWorkbench를 연결하고 재개, 실패, 취소, 근거 부족, 피드백 후보 경로를 제공한다. 질문 본문/이력을 localStorage에 저장하지 않는다.
- 시험: 실제 RuntimeService + DB + 큐 + loopback 모델로 두 턴, 권한 철회 직전/직후 전송, 프로세스 재시작, 응답 소실 재시도, 동시에 같은 nonce 제출, 다른 사용자/공간 접근, 근거 없는 답변을 확인한다. 삭제/복구의 기능 연결은 P9와 함께 검증하며 미지원 범위의 차단을 먼저 해제하지 않는다.

### P2. 버전 비교·선택 검토·의존 복원

- 관련: VER-004~010, REV-004~007, KNO-014.
- 기존 `VersionService`, `handleVersionRoute`, `VersionsPanel`을 인증된 호스트와 앱에 연결한다.
- 당시 메타데이터가 없는 버전은 미확인으로 표시한다. 복원은 현재 ACL을 유지한 새 검토 제안이며 자동 발행하지 않는다. 사람이 수정한 본문·보호 구간·현재 의존성을 보존하고 충돌을 보여준다.
- 선택 검토는 의존성 검사를 통과한 묶음만 분리하며 새 묶음에는 독립 검토가 필요하다. 기존 승인을 재사용하지 않는다.
- 시험: 본문/속성 비교, 페이지를 가로지르는 의존 복원, 보호 내용 충돌, 동시 변경 후 오래된 preview 거부, 현재 권한 철회, 댓글 위치의 버전 간 확인.

### P3. 사용자 알림·검토함

- 관련: CLB-003~007, LIF-002, UX-003.
- `CollaborationService`, HTTP, `notifications.tsx`를 기존 댓글·구독·governance 경로와 연결한다. 개인 설정, 읽음 처리, 검토 기한과 실제 미처리 검토함을 제공한다.
- 현재 자격 있는 검토자만 작업을 받는다. 배정/알림 자체는 원본 열람권이나 검토 승인을 만들지 않는다. 기한 검토와 일간/주간 요약은 기존 지속 작업에 연결하고 호스트 종료/재시도/중복을 처리한다.
- 인앱 전달을 기본으로 한다. 이메일 전달 어댑터는 기존 승인된 목적지 설정이 있을 때만 활성화하고, 전달 설정 없음/게이트웨이 수락/수신 확인을 구분한다. 실제 외부 메시지 발송은 이 개발 작업에서 실행하지 않는다.
- 시험: 설정 변경과 대기 요약, 시간대, 재시도/중복, 권한이 사라진 제목·링크 미노출, 검토자 회수, 인앱 읽음과 이메일 상태의 구분.

### P4. 계정·세션 관리 연결

- 관련: IAM, ACL; 세부 동작은 `server/identity/INTEGRATION.md`, `NATIVE_INTEGRATION.md`를 따른다.
- 기존 `createIdentityRuntime`을 인증 생성과 연결하고 identity HTTP 및 IdentityManager를 앱에 연결한다. 본인 세션 목록/철회/전체 로그아웃을 실제로 동작시킨다.
- 승인된 디렉터리 바인딩과 긴급 접근 모듈은 서버에 명시적으로 구성된 경우에만 노출한다. Owner/reviewer를 시스템 긴급 승인자로 추정하지 않는다. 디렉터리 가용성 문제를 오래된 권한의 무기한 사용으로 처리하지 않는다.
- 같은 canonical authorizer를 유지한다. 긴급 접근도 원본 상한을 우회하거나 발행·관리 권한을 만들지 않는다.
- 시험: 다른 사용자의 세션, 현재 세션 철회 후 쿠키/UI 정리, CSRF, 만료/중지 신원, 디렉터리에서 제거된 멤버, 별도 설정 없는 긴급 기능 비활성, 본문 상한.

### P5. 기존 3역할 공간 호환

- 관련: IAM/ACL, AGENTS의 미이관 공간 3역할 유지 계약.
- 기존 계약을 변경해 운영자 이관을 강제하는 대신, 검증된 기존 issuer/subject와 이관 전 membership을 바탕으로 제한된 호환 경로를 구현한다.
- 기존 역할이 허용했던 읽기·작성·검토/발행만 정확히 보존한다. reviewer를 Maintain/Admin/Owner로 일괄 승격하지 않는다. 명시적 이관 이후에는 호환 경로를 폐기하고 제품 grant를 사용한다.
- 알 수 없는 신원, 비활성 신원, 검증되지 않은 과거 membership은 계속 격리한다. 현재 원본 제한과 독립 검토·발행 재검사는 유지한다.
- migration은 기존 파일을 수정하지 않고 새 번호로 추가한다. 공개 PR #30의 migration 110과 충돌하지 않도록 예약한다.
- 시험: 실제 이전 스키마에서 신규 스키마로 이관한 DB, 세 역할별 기존 행동, 권한 상승 거부, fresh OIDC 검증, 철회, 명시적 공간 이관, 재로그인으로 회수한 grant 복구 금지. 이 변화에는 별도의 권한 코드 리뷰가 필요하다.

### P6. 근거와 연결된 지식 갱신·답변 재편입

- 관련: CORE-003/006/007/010/011, KNO-002~006/009/012~014, QNA-007.
- 기존 편입/정련 서비스와 `fileAnswer`를 확장해 새 분석 페이지뿐 아니라 기존 페이지의 결론·조건·예외·연결을 보완하는 변경 후보를 만든다. 답변을 붙여넣는 것만으로 종합 완료를 표시하지 않는다.
- 후보는 기존 페이지 갱신, 별도 분석 생성, 중복으로 변경 없음의 이유를 보여준다. 실제 의미 종합은 모델 경로에서 수행하며 구조 처리와 구분한다. 모델 미설정/실패를 가짜 종합으로 대체하지 않는다.
- 현재 페이지 기준 버전, 원본 버전/위치, 전체 모델 입력 계보, 파생 답변 관계를 고정한다. 같은 원본에서 파생된 여러 답변을 독립 증거로 세지 않는다.
- 편입 변경과 주장/조건/시간·상충 후보를 연결한다. 검토 승인, 실행 검증, 공식성, 현재 적용 가능성을 분리한다. 결과 보고/반증은 재검토 후보이며 자동 사실 승격이나 자동 공식 발행을 만들지 않는다.
- 시험: 같은 조건의 반증, 다른 환경의 실패, 중복 근거/답변 재제출, 보호 구간, 검토 후 원본·기준 변경, 원본 철회, 원자 발행, 모델 오류. 기존 CORE-003 주제+두 개념 시험도 유지한다.

### P7. 검증된 도구 자료 수집

- 관련: COL-003/005/008~011, INT-005/007.
- 첫 지원 대상은 저장소에 익명 fixture와 파서가 있는 OpenCode 2.2.2의 명시적 선택 자료다. 실제 설치 버전/응답과 fixture를 다시 대조한다. 다른 버전은 검증 전 지원 표시하지 않는다.
- 서버가 승인한 호스트/사용자 연결을 통해 세션과 artifact를 직접 확인하고 선택 ID·소유자·허용 경로를 결합한다. 요청 본문의 sessionId나 제외 목록만으로 신뢰를 부여하지 않는다.
- 서버 제외 정책, 원본 스냅샷, 중복/순서 처리, 현재 권한을 검사한 뒤 기존 개인 입력 경로에 접수한다. 도구 실행 기록의 성공 주장을 독립 검증으로 바꾸지 않는다.
- 연결 중 실행만 지원한다. 로컬 파일 전체 탐색이나 상주 daemon을 추가하지 않는다. 서버에서 도달 가능한 승인된 수집 endpoint가 없는 경우 비활성을 유지한다.
- 시험: 정상 fixture, 세션 위조, 타인 artifact, 제외된 세션/내용, 공급자 버전 변화, 순서 역전/중복, 부분 응답, 연결 철회. loopback 수집기 시험과 실제 설치 검증을 구분한다.

### P8. 개인 로컬 작업본의 실제 서버 연결

- 관련: CORE-009, KI-01~07; `docs/KNOWLEDGE_INTEGRATION.md`, `LOCAL_WIKI.md`, agent 서비스의 기존 개인 작업본 계약.
- 기존 connector 요청 형식을 실제 인증된 서버 agent 경로에 연결한다. 공통 RuntimeService/발행 규칙을 사용하고 합성 개발 서비스와 실행 모드를 구분한다.
- 실제 공간/주체 ID와 connector의 개인 작업본 표시용 ID를 서버에서 일관되게 결합한다. `localCopyAllowed`, 범위 자격증명, 최신 권한을 매 조회/동기화/제안에서 검사한다.
- 선택한 개인 revision으로 공유 제안을 만든다. 현재 개인본을 몰래 바꿔 제출하거나 즉시 공유 발행하지 않는다. 원본 참조를 검증하고 의존 변경은 검토 가능한 한 묶음으로 처리한다.
- 기기 충돌의 양쪽 본문과 선택 revision을 보존한다. 연결 종료 후 동기화하지 않고 다음 연결에서 재개한다. 권한 불명/철회 시 보호 캐시 접근을 차단한다.
- 시험: 실제 HTTP/DB/자격증명으로 개인 쓰기·동기화·읽기·공유 제안, 같은 ID의 여러 공간, 기기 충돌, 토큰 철회, 로컬 복사 금지, 원본 위조, 재시도와 공유 기준 충돌.
- ADR 004는 계속 제안 상태다. 여기서는 이미 존재하는 공통 서버/개인 작업본의 연결을 구현하며 ADR 전체 채택이나 KI 전체 운영 인수를 선언하지 않는다. 기존 계약을 넘어서는 DTO/권한 정책 변경은 구현 전에 별도로 드러낸다.

### P9. 사용자 데이터의 휴지통·복구·보존·삭제·철회

- 관련: LIF-004/005/007, VER-009/012, ACL-008.
- 질문/답변/피드백, 에이전트 개인 작업본·결과, 버전 속성·복원 후보가 기존 삭제/철회 그래프에서 빠져 있는 조건을 해소한다. 개인 이력 삭제와 원본 철회가 후속 조회·검색·모델 입력·재시도·복원 후보에 전파되어야 한다.
- 휴지통과 정책에 따른 유예 기간, 사용자 복구를 포함한다. 고유 ID·이력을 보존하고 복구 시 현재 권한을 다시 검사하며 경로 충돌을 명시적으로 해결한다. 백업 재해복구와 구분되는 제품 기능이다.
- 법적 보존/정책 상한과 권한을 검사한다. 삭제 영향 미리보기와 기준 해시를 고정하고 현재 상태를 재검사한다. 감사용 최소 메타데이터와 제거할 본문을 구분하며 불변 승인 기록을 임의로 다시 쓰지 않는다.
- 초안·발행본·원본 버전의 보존 정책을 구분하고 대상 선정, 유예 후 처리, 기존 지속 작업에 연결한 주기 실행을 구현한다. 발행본을 보존하는 동안 근거 계보를 임의 정리하지 않는다. 실제 회사의 기간/보존 의무를 추정해 기본값으로 활성화하지 않고 합성 정책으로 검증한다.
- 알 수 없는 참조나 미지원 형식은 명시적으로 거부한다. 기존 `ERASURE_*_UNSUPPORTED`를 시험 없이 없애지 않는다. 실제 사용자 자료 삭제를 개발 중 실행하지 않는다.
- 외부 백업에서의 물리 삭제, 백업 이관/재해복구, 실제 회사의 보존 정책 설정·운영 인수는 이번 범위 밖이다. 이 한계는 UI/문서에 남기고 전체 영구 삭제 완료로 표현하지 않는다. 기존 복구 경로의 tombstone 재적용·재노출 차단은 그대로 유지한다.
- 시험: 각 저장 형식의 합성 삭제 그래프, 휴지통 복구의 ID/이력·현재 권한·경로 충돌, 보존 대상과 유예 기간, 외부 의존 문서, 법적 보존, 동시 작업의 late write, 주기 실행 재시도, 삭제된 원본을 참조한 과거 버전·복원 후보 차단.

### P10. 실제 지식 발전 경로의 평가·검토 비용 기록

- 관련: CORE-012, EVA-001~006, UX-003, NFR-009.
- 사전 작성 위키 비교 실행기와 별도로 실제 편입→검토→발행→질문→점검을 최소 3차례 실행하는 평가 경로를 추가한다. 원본만/정적 위키/유지 위키의 대조군, 같은 모델·예산·권한·자료를 고정한다.
- 평가용 정답과 업무 홀드아웃을 작업 입력에서 분리한다. 평가 중 생성한 답변은 평가 위키에 재편입하지 않는다. 근거 정확도, 조건·반증 반영, 과거 정답 회귀와 실패·미완료·시간초과를 모두 기록한다.
- 모델·정리 호출 비용, 검토 대기/작업 시간, 반려/재제안/재검토와 변경 수를 기록한다. 실제 인간 작업 시간은 명시적인 시작/완료 사건에서만 계산하고 화면 체류시간을 대신 사용하지 않는다. 기록이 없으면 미측정이다.
- fixture 실행은 구조/회귀 증거이고 실제 모델/도메인 판정과 구분한다. 승인된 평가셋·실제 업무가 없으면 성능 개선을 주장하지 않는다. 기존 100답변/95% 등 기준을 낮추지 않는다.
- 시험: 새 근거와 반증으로 기존 페이지가 바뀌는 3회 순환, 정적 대조군 불변, 동일 원본 중복 미증가, 홀드아웃 유출 차단, 실패 분모 보존, 비용 합계, 검토 시각 중복/누락.

## 의존 관계와 검증

P3~P5는 기존 모듈의 호스트 연결/호환을 중심으로 독립 PR로 준비할 수 있다. P1/P2/P8의 저장 테이블은 이미 있으므로 P9의 해당 삭제·복구 fence를 먼저 구현하고 그 위에 호스트 연결 PR을 쌓는다. 연결 중 저장 형태가 확장되면 같은 PR에서 그래프/시험도 보완하며 보호되지 않은 쓰기를 먼저 활성화하지 않는다. P6은 기존 정련과 편입을 재사용하고 P1의 개인 대화를 필수로 요구하지 않는다. P7은 별도의 연결이다. P10은 P6의 실제 지식 갱신 경로를 사용하며 P1/P3의 검토/대화 기록은 선택한 평가 시나리오에만 포함한다.

각 PR에서 의미 있는 실패 재현 테스트를 먼저 작성한 뒤 구현한다. `npm run check`와 변경한 서버 경로의 격리 PostgreSQL 회귀를 수행하고 최종 커밋의 CI를 확인한다. UI 변경은 실제 브라우저 1440px/390px 캡처와 키보드·오류·권한 변경 확인을 남긴다. 브라우저/DB/모델 환경이 막히면 미실행으로 기록하고 해당 인수 증거를 갖췄다고 표시하지 않는다.

독립 리뷰는 현재 권한, 전체 모델 입력, 승인 기준, 동시 변경, 재시도, private UI 상태 정리를 중점으로 한다. feature branch의 최종 커밋 기준으로 검증 결과를 PR에 기록한다. `CURRENT_STATUS.md`, `AGENT_HANDOFF.md`, 필요한 실패 기록을 기능별로 갱신한다. 실제 사내 모델 품질·운영 인수는 개발 회귀 결과와 분리한다.

## 아직 확정하지 않은 제품 결정

1. 승인 범위는 현재 현황의 잔여 기능 P1~P10이며, 확장·선택 요구사항 자체는 그대로 보존한다.
2. 첫 실제 업무 사례와 도메인 정답 판정자. 구현/합성 회귀는 이 결정 없이 진행 가능하지만 실제 유용성 판정은 불가하다.
3. 사내 수집 endpoint·디렉터리/긴급 접근·메일 전달 설정. 코드는 명시 설정을 요구하고 합성 endpoint로 검증하며 운영 설정을 만들어내지 않는다.

이 문서의 리뷰는 구현 범위/방식을 검토하기 위한 것이며 코드 구현 완료, 실제 모델 품질, 배포, ADR 전체 채택을 뜻하지 않는다.

## 설계 검토 기록

독립 builder 검토에서 사용자 휴지통 복구와 제품 보존 실행이 운영 고도화로 빠질 수 있다는 두 가지 질문을 받았다. 원래 LIF-004/005 및 VER-012의 기능 계약이므로 두 항목을 P9에 명시적으로 포함했다. 이는 작성자의 범위 제안이며 회사의 실제 보존 기간이나 운영 배치 인수를 승인한 것이 아니다. 사용자는 설계 제시 후 “진행해”로 P1~P10 구현과 개별 PR 생성을 승인했다. 머지는 승인 범위에 포함되지 않는다.

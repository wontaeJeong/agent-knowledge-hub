# 로컬 우선 개인 위키와 공유 변경 제안

상태: 사용자 승인 컨셉의 첫 구현 설계, 2026-10-29. 운영 수용 완료 선언이 아니다.

## 합의와 목적

- 개발자 하네스와 Codex/OpenCode Desktop·Cowork를 사용하는 비개발자가 대상이다. 별도 제품 데스크톱 앱을 만들지 않는다.
- 접근·로컬 보관이 허용된 최신 위키 텍스트, 연결, 출처 식별자와 버전을 로컬에 보관한다. 첨부·원본 본문·전체 과거 이력은 복제하지 않는다.
- 개인 공간은 PR 대기함이 아니라 개인 지식을 지속 발전시키는 서버 공간이다.
- 로컬 변경은 연결 중 자동 동기화한다. 종료 후 상시 실행은 먼 미래 범위이며 이번 구현에서 서비스·시작 프로그램·OS 스케줄러를 설치하지 않는다.
- 여러 PC·에이전트의 동시 작업을 고려한다. 겹치는 변경은 양쪽을 보존하고 에이전트가 제안한 병합안을 사람이 확인한다.
- 공유 공간 반영은 명시적 변경 제안·검토·발행이다. 개인 자동 저장이 공유 지식을 발행하지 않는다.
- 공유 공간의 레벨·계층·승격 경로는 미정이다. 문자열 공간 ID를 사용하고 조직 계층을 하드코딩하지 않는다.

네트워크와 반복 본문 전송 감소는 목표다. 성능·지식 품질 개선은 실측 전 주장하지 않는다. Ingest → Query → Lint·재편입과 출처 계보를 유지하며 Git 유사 UX를 목적으로 위키를 단순 파일 CRUD로 축소하지 않는다.

## 첫 수직 구현과 남은 제품 범위

공통 Node 로컬 커넥터, STDIO MCP, CLI, 지속 로컬 상태, 실제 HTTP 동기화와 검토 경로를 구현한다. 상대 서비스는 **합성 자료 전용 loopback 개발 서비스**로 제공한다. 기존 React/localStorage 데모와 데이터는 그대로 유지한다. 새 서비스는 운영 PostgreSQL/SSO 서비스를 대체하지 않는다.

첫 구현에서 두 독립 로컬 디렉토리 → 개인 공간 → 공유 변경 제안 → 승인/발행을 실제 통신으로 시험한다. 인증은 개발자가 설정한 토큰/주체/역할 매핑이며 요청 본문으로 신원을 결정하지 않는다. 배포 서버·기존 UI 통합·Windows 설치형 배포·실제 앱별 호환 시험·자연어 의미 병합은 미구현으로 남긴다. 기존 251개 수용 기준은 그대로 유지한다.

## 데이터와 책임

- `Page`: 안정적 `id`, `title`, `content`, `links`, `sourceRefs`, `version`, `spaceId`, `localCopyAllowed`. sourceRefs에는 ID/버전/위치만 두며 원본 본문을 넣지 않는다.
- 로컬 레코드: 서버 기준 `base`, 현재 `draft`, 충돌 시 원격 `incoming`, 전송 중복 방지용 변경 ID. 서버 스냅샷·로컬 수정·충돌을 한 JSON 파일의 원자 교체로 저장한다.
- 개인 공간: 인증 주체별 별도 페이지 컬렉션. 공유본과 개인본은 별도로 보존하며 개인 파생본은 `upstream` ID/버전으로 공유 기준을 고정한다.
- 변경 제안: 개인 revision과 공유 기준 revision·원본 참조를 고정한 스냅샷. 이후 개인 편집이 제출된 제안을 바꾸지 않는다.
- 제출자는 `personalVersion`으로 선택한 개인 revision을 고정하고 서버는 원자적으로 재검사한다. 클라이언트는 권한 갱신 전에 선택을 캡처하며 다른 기기 변경을 자동으로 제출하지 않는다. 개인본 슬롯은 ID당 하나이고 다른 공간의 동일 ID 입력은 보존적 거부한다. 공간 간 출처를 묵시적으로 재사용하지 않는다.
- 승인: 검토자 역할과 승인 스냅샷에 연결. 발행 직전 현재 공유 버전·원본 범위·권한 재검사. 반복 발행은 같은 결과를 반환한다.

초기 동기화는 허용 최신 텍스트 전체 스냅샷이며, 업로드는 변경 페이지만 보낸다. 다운로드 delta cursor는 후속 최적화다. 최신 전체 스냅샷을 변경분 다운로드라고 표현하지 않는다.

## 로컬 저장과 동시성

커넥터가 관리하는 JSON 저장소를 정본 로컬 작업본으로 먼저 사용한다. Markdown 폴더 직접 편집·파일 감시는 후속 어댑터다. 이를 통해 비개발자에게 파일 배치나 commit을 요구하지 않고 여러 페이지 변경을 한 요청으로 처리한다.

프로세스는 작업 디렉토리에 배타 잠금을 잡는다. 같은 디렉토리를 여러 호스트가 동시에 열면 두 번째 연결은 명시적 오류로 종료한다. 다른 PC/디렉토리 간 동시성은 서버 기준 버전으로 제어한다. 정상 종료는 잠금을 해제하며 비정상 종료의 잠금 복구는 프로세스 존재 확인 후 진행한다.

쓰기 전에 전체 입력을 검사하고 임시 파일에 저장한 뒤 rename한다. 손상된 상태는 빈 상태로 바꾸지 않고 오류를 내서 원본 파일을 보존한다. 네트워크 전송 전에 draft를 디스크에 기록한다. 서버가 수락한 뒤 응답이 유실돼도 같은 변경 ID 재전송으로 중복 버전이 생기지 않는다.

연결 시 즉시 동기화를 시도하고, 연결 동안 직렬 polling한다. 실패는 오류 상태와 미전송 변경으로 남긴다. 종료는 진행 중 요청을 취소하고 로컬 변경을 보존한다. 재시작은 저장된 기준에서 재개한다. 무제한 병렬 요청·타이머 중첩을 만들지 않는다.

## 충돌과 병합

서로 다른 문서는 독립적으로 동기화한다. 같은 기준의 두 다른 편집이 오면 `base/draft/incoming`을 유지한다. 동일 내용 재전송·한쪽만 바뀐 경우만 자동 수렴하며, 첫 구현은 일반 텍스트의 비중첩 자동 병합도 보수적으로 충돌 처리한다. 의미 병합보다 손실 방지를 우선하는 구현 선택이다.

병합안 작성과 적용은 별도 동작이다. MCP는 충돌을 읽고 병합안을 준비할 수 있으나 **확정 도구는 제공하지 않는다**. 사용자는 CLI에서 충돌의 로컬/원격 revision과 제안 해시를 확인한 뒤 적용한다. 확인 시 원격이 다시 바뀌면 재충돌하고 승인되지 않은 병합으로 덮어쓰지 않는다. 실제 앱의 네이티브 확인 UI는 버전별 호환 검증 뒤 추가한다.

## 권한·반출·로컬 조회

로컬 저장은 사실상 반출이다. 읽기 권한과 로컬 보관 허용을 구분하며 `localCopyAllowed`가 없는 자료는 복제하지 않는다. 개발 서비스는 합성 자료만 이 값을 부여한다. 실제 자료의 등급별 허용·기기 암호화·보관 기간은 제품/보안 결정 전 운영 차단 조건이다.

기존 ACL-007·013을 완화하지 않는다. 커넥터의 본문 읽기·검색 전에 서버에서 현재 허용 페이지 목록/버전을 확인한다. 응답이 없으면 보호된 캐시를 제공하지 않는다. 본문은 로컬에서 읽되 권한 검사 통신은 남는다. 따라서 이번 구현은 완전한 오프라인 열람을 약속하지 않는다. 이미 로컬에 반출된 평문을 사용자/OS에서 완전히 회수할 수 없다는 LIF-010 한계는 그대로다.

전체 스냅샷에서 사라진 캐시는 제거하고 관련 draft도 격리 없이 제공하지 않는다. 개인 미전송 편집과 강제 삭제가 충돌하면 노출 방지를 우선하며 운영 보존 정책은 별도 확정한다. 명시적 삭제 동기화 API는 후속 범위다. 서버에 없는 신규 개인 문서는 자신의 로컬 작업으로 유지한다.

토큰은 환경변수로 주입하며 위키 상태·오류·STDOUT에 저장하지 않는다. loopback 개발 HTTP 외의 실제 서버는 HTTPS만 허용한다. 리다이렉트는 따라가지 않고 토큰을 다른 주소로 보내지 않는다. 요청·응답 크기와 대기 시간을 제한한다. 원본 조회는 별도 서버 권한 경계이며 커넥터에 원본 수집/다운로드 도구를 추가하지 않는다.

## MCP와 호스트 포장

`wiki_status`, `wiki_search`, `wiki_read`, `wiki_write`, `wiki_sync`, `wiki_conflicts`, `wiki_prepare_merge`, `wiki_propose_change`를 제공한다. 도구 응답은 개인/공유·버전·미동기화·오류를 구별한다. 공유 승인·발행과 병합 확정은 MCP 도구에서 제외한다. 로컬 글쓰기와 서버 공유 승인을 같은 권한으로 취급하지 않는다.

공통 실행 엔트리를 OpenCode V2 설정·Codex 설정으로 연결하는 예시를 제공한다. Claude Desktop `.mcpb` 및 Cowork 플러그인의 포장·서명·실기 호환은 후속 작업이며 설정 예시를 설치형 지원 완료로 표시하지 않는다.

2026-10-29 문서 확인: [OpenCode V2 MCP](https://opencode.ai/v2/docs/mcp-servers), [Codex MCP](https://developers.openai.com/codex/mcp/), [Claude 확장](https://support.claude.com/en/articles/10949351-getting-started-with-local-mcp-servers-on-claude-desktop), [Cowork/플러그인 구분](https://support.claude.com/en/articles/11725091-when-to-use-desktop-and-web-connectors). [Claude 원격 커넥터](https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp)는 클라우드에서 접속하므로 사내망 접근의 대체재로 가정하지 않는다. 문서 확인은 실기 검증이 아니다.

## 평가와 기존 지식 영향

- 동기화: 두 디렉토리, 재연결, 미전송 보존, 중복 요청, 같은 페이지 충돌, 손상 파일, 인증 실패, 권한 제거를 실제 파일·HTTP로 시험한다.
- 공유: 개인 저장 후 공유본 불변, 제출 스냅샷 고정, 비검토자 발행 거부, 기준 변경 시 승인/발행 차단, 재시도 중복 방지.
- MCP: 공식 SDK 클라이언트로 별도 프로세스를 실행해 검색/수정/오류/종료와 재시작을 시험한다. 이 시험은 Codex/OpenCode/Cowork 실기 시험이 아니다.
- 성능 후속: 같은 데이터·권한·질문에서 원격 본문 조회 대비 초기 전체 다운로드, polling, 권한 검사, 로컬 검색 비용과 p50/p95 지연을 함께 측정한다. 실패의 빠른 종료를 개선으로 세지 않는다.
- 품질 후속: `docs/EVALUATION.md`의 계보·재편입·상충·권한 회귀를 적용한다. 파일/연결 수 증가를 지식 발전으로 세지 않는다.

연결되는 기존 요구사항: GOV-003·004, ACL-001·004~007·009·013·014, EDT-002·003, VER-005·007·009, REV-004~006, LIF-008~010, INT-001·002, CORE-002~007·009~012. 첫 구현의 로컬/합성 통과가 해당 수용 기준 전체 완료는 아니다. North Star 의미와 현행 런타임 규칙은 바꾸지 않는다.

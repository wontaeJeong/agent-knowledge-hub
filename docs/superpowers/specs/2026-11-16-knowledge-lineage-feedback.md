# 일반 편입의 주장 계보와 검토 피드백

Task 5 · KNO-002~006/013/014. North Star의 근거/추론 분리, 시간/조건 보존, 검토 가능한 발전과 Ingest → 검토/발행 → 정정/재검토 → 후속 Ingest를 개선한다. 새 원본을 독립 문서로 추가하는 것만으로 지식 축적을 주장하지 않는다.

- 일반 모델 Ingest도 기존 답변 재편입과 같은 `candidates` 계약을 받는다. 서버가 제안 페이지, 실제 공급 원본, 정확한 인용 위치(JavaScript UTF-16 문자열 오프셋), 원본 fingerprint를 결합한다. 모델이 반환한 검증 시각/독립 실행 상태는 허용하지 않는다. 후보는 승인 전 배치에만 있으며 정본 발행 트랜잭션이 새 발행 버전의 미검증 주장·원본 근거·상충/재검토 요청을 함께 저장한다. 같은 원본 본문은 같은 계보 root를 사용한다.
- `POST /api/v1/changesets/:id/reject`는 `hash, reason`을 받는다. 이전 클라이언트의 hash-only 요청은 `사유 미기록`으로 기록한다. 웹에서는 이유를 입력해야 반려할 수 있다. 이유·검토자·시각을 저장하고 동일 사유 재시도는 같은 결과, 다른 사유 덮어쓰기는 충돌이다. 검토 기록은 제안 내용 해시와 분리한다.
- 후속 모델 입력에는 현재 ACL에서 전체 영향 원본/페이지를 볼 수 있는 반려 제안과 사유, 발행 완료된 사람 편집 사유, 현재 보호 사유를 넣는다. 관련 계보를 입력 envelope에 고정하고 저장 직전에 피드백과 사람 결정을 다시 검사한다. 같은 원본과 동일한 제안 내용의 반복은 서버가 `REJECTED_PROPOSAL_UNCHANGED`로 차단한다. 순서만 바꾼 sourceIds/links/facts/updates도 변경으로 보지 않는다. 유의미하게 수정했는지의 의미 판단은 모델 품질 평가와 사람 검토가 필요하다.
- 원본 정정은 기존 원본/주장을 변조하지 않는다. 원본 등록 트랜잭션에서 영향을 받은 발행 버전별로 원본·정정본·이유·주장과 재검토 요청을 연결하고, 해당 원본에 의존하던 미발행 배치의 승인을 무효화한다. 버전별 요청은 다른 페이지의 ACL을 결합해 전체 요청을 숨기거나 넓히지 않는다. 조회 때 원본/정정본/발행 버전/주장 전체 현재 ACL을 재검사한다. 일반 Ingest에는 정정 전후 원본과 이유를 함께 넣는다.
- 보호된 페이지는 일반 모델 편입에서도 자동 변경안을 저장하지 않는다. 권한·기준 버전·원본 변경, 모델 실패, 재시도에 대한 기존 원자적 발행 계약을 유지한다.

새 테이블·필수 서비스·정책 버전 변경은 없다. 기존 PostgreSQL 배치 JSON과 refinement 저장소를 사용한다. 피드백/수정 이력이 각 100개를 넘으면 `MODEL_CONTEXT_LIMIT`으로 명시적으로 중단하며 근거를 조용히 생략하지 않는다. 모델 전송 바이트/응답/작업 예산도 기존 정책을 따른다. 실제 사내 모델의 조건/시점/상충 해석 정확도, 동의어 반복 제안 판단, 후속 업무 효과와 전체 운영 인수는 이 합성 회귀로 증명하지 않는다.

검증은 실제 PostgreSQL 회귀, loopback OIDC/모델 HTTP 및 MCP SDK 통합, 웹 입력 회귀, 1440/390 실제 브라우저 캡처로 수행한다. 원본·질문 결과·검토 승인·독립 실행 증거는 서로 다른 상태로 유지한다.

## PR 검토 P1 보완 — 반려안 전체 의존성

반려 피드백은 현재 페이지/원본 ID 목록뿐 아니라 제안의 외부 links, 기존 대상, 이전 입력/컨텍스트, 모든 과거 버전의 원본·파생 관계 및 문서 상위 경로 전체를 현재 ACL로 확인한다. 하나라도 읽을 수 없으면 이유·본문·ID를 포함한 해당 피드백 전체를 모델 입력에서 제외한다. 아직 발행되지 않은 같은 변경 집합의 새 페이지 사이 링크는 기존 리소스 조회로 오인하지 않는다.

허용된 피드백은 완전한 별도 envelope를 만든 뒤 일반 편입의 모델 입력 envelope에 합친다. 과거 페이지에 관한 검토 결정은 현재 권한으로 읽을 수 있어야 하지만 그 페이지가 현재 추천 대상일 필요는 없다. 실제 종합 페이지 목록은 기존 현재 추천 조건을 계속 따르며, 피드백 의존 페이지의 버전/ACL/전송 정책은 모두 고정한다. 답변 재편입은 원래 답변 envelope의 모든 페이지/원본 안에 완전히 포함되는 피드백만 사용할 수 있고 답변 범위를 늘리지 않는다. 모델 전송 직전과 제안 저장 직전에 피드백·사람 결정·전체 리소스 범위를 다시 확인한다.

실제 PostgreSQL 회귀는 페이지/하위 페이지/원본 철회, 제안 로컬 새 링크, 현재 종합에서 제외된 과거 링크, 읽기 허용/전송 정책 거부, 답변 범위 밖 피드백을 확인한다. 실제 HTTP 모델의 beforeCall 이후 링크/원본/정책을 철회한 경우 provider가 요청을 받지 않는 것도 검증한다. 링크를 화면에서만 숨기고 원래 반려 본문을 보내는 처리는 허용하지 않는다.

# Task 8 — subscriptions and event notification contract

Requirements: CLB-004–006. This extends the existing collaboration worker and notification/digest services, with no new infrastructure. It supports the review/maintenance portion of Ingest → review → publication → Lint by surfacing actionable changes under current authorization. It changes no North Star definition and makes no knowledge-quality or downstream-performance claim.

- The canonical topic taxonomy is `Page.category`. The UI explicitly calls it “주제 (문서 분류)”; this is not a fabricated topic ID. Topic discovery includes only currently readable pages. Matching uses the current category, including after category changes. Existing individual document subscriptions remain compatible and now join category/space comment recipients.
- `GET/POST /api/v1/collaboration/subscriptions` lists or idempotently enables/disables the authenticated actor's current-space or category subscription. The server rejects caller-supplied principal/workspace fields. An inaccessible topic can still be unsubscribed without revealing its existence. Space subscriptions never grant access.
- Migration 120 adds a durable identifier-only outbox. DB triggers capture committed publication, pending-batch/hash and terminal `dead` job/attempt records in their originating transactions. The existing worker projects at most 100 pending events per tick. Retries and overlapping document/topic/space subscriptions create one recipient notification per event. Existing historical records are not backfilled.
- Expiry is explicit lifecycle metadata `effectiveUntil` (ISO UTC, nullable), managed by the existing lifecycle CAS API with current lifecycle and protection capabilities. The editor exposes the setting only with both capabilities and requires a reason. The worker emits once per page/deadline. Extending/removing the deadline makes old expiry notices ineligible. It does not delete documents, approve knowledge or change the existing recommendation policy.
- Publication and expiry require a current matching subscription. Review requests additionally use the exact canonical whole-batch/current-source and independent review qualification checks; only still-pending content is displayed. Generic review labels link to the real review screen. New-page proposals can reach space subscribers who qualify; category matching begins when a canonical categorized page exists.
- Terminal failures notify only the explicit human job actor or current explicitly assigned service sponsor. Every input/envelope page and source is reauthorized. Provider error text is never copied into notifications. A failure link opens the actor's existing job history. Operational alerts remain separate.
- All new content passes the same gate at fanout, in-app reads, acknowledgement, processing and digest finalization. This includes current active identity, membership/capability, all influencing source/page ancestry, current subscription and current event state. Only IDs, a permitted title or fixed event label, and a local app link enter the public DTO; no envelope/ACL data is returned. Recipient discovery uses subscriptions and explicit job responsibility, never compatibility membership rows as authority.
- `POST /collaboration/notifications/:id/process` records per-recipient processing independently of email delivery and actual workflow execution. Read and processed marks are idempotent; they neither approve a batch nor repair a failed job. Processing labels are for personal tracking. New kinds appear in the consolidated collaboration panel; the legacy workflow comment list remains comment-focused.
- Retention inventory explicitly classifies both new tables and hashes private category targets before service-memory inspection. Workspace erasure/recovery removes subscription configuration rather than replacing composite-key targets; event→batch/job/page and notification→event lineage participates in the existing erasure graph.
- Daily/weekly digest planning, quiet hours, recipient directory proof, final ACL gate, missing-configuration status, delivery lease and gateway deduplication reuse the existing service. Events without eligible content produce no message. Tests use local synthetic identities and an in-process finalizer, with no external messages. Actual company directory/gateway and operational acceptance remain unverified.

Evaluation: domain PostgreSQL regressions cover subscription idempotence, current category, overlap deduplication, whole-source revocation, stale review/deadline, ownership, comment integration and final-gate revocation; native runtime HTTP covers session, CSRF, strict DTOs and current ACL. Actual 1440/390 browser evidence uses synthetic API fixtures and is documented separately. These checks validate behavior, not semantic knowledge quality.

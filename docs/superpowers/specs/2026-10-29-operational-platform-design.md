# 동시접속 10명 이하 운영형 지식 플랫폼 설계

상태: 승인 요청. 구현 계획·구현 완료·운영 인수 결과가 아니다.
기준: origin/main `94ead71`, North Star, 기존 239개 + CORE 12개 요구사항.

## 1. 사용자 결정과 완료 경계

- 미구현 기능을 실제 운영 가능한 수준으로 구현하고 검증 후 PR 생성·머지까지 진행한다. 사용자가 머지를 사전 요청했다.
- 동시접속 10명 이하를 초기 부하 계약으로 한다. 대규모 확장 최적화는 후순위다.
- 운영은 Kubernetes다. 로컬 개발·통합 검증도 kind를 기본으로 하고 Compose를 필수로 만들지 않는다.
- 현재 모델은 DeepSeek이며 사내 설치 시 온프레미스 모델로 교체할 수 있어야 한다.
- 운영 신원은 사내 SSO다. 개발에서는 Keycloak으로 실제 인증 흐름을 검증한다.
- API 비밀값은 사용자가 허용한 로컬 설정에서 필요한 값만 읽고 화면·로그·Git·PR·브라우저 번들에 노출하지 않는다.

구현 담당자의 제안(아직 사용자 승인 전): TypeScript/React/PostgreSQL과 기존 지식 도메인을 유지하고, 표준 OIDC 서버 세션, Kustomize base/overlays, 단일 앱과 DB 영속 작업자를 사용한다. ADR 004의 공통 서버 정본을 채택하는 방향이다. 이 설계 승인 후 별도 ADR 상태를 갱신한다. North Star의 의미는 바꾸지 않는다.

완료는 코드 작성, 자동 회귀, kind 실행, 외부 모델 시험, 사내 인수를 나눠 기록한다. 사내 IdP·도메인·TLS·스토리지·네트워크·운영 책임자의 제공/승인이 없으면 그 환경의 완료를 선언하지 않는다. 누락은 차단 조건으로 남기며 mock이나 개발 설정으로 대체하지 않는다.

## 2. 목표·금지·유예

목표는 원본 → 기존 지식 재구성 → 다중 페이지 변경 집합 → 검토·발행 → 인용 Query → 재편입 → Lint/업무 결과 환류의 서버 순환이다. 개인 작업본 동기화와 공유 지식 발행은 분리한다. 사람의 편집·탐색·검토 기능도 유지한다.

다음은 금지한다: localStorage 정본, 브라우저 역할을 인증으로 사용, 모든 사용자의 관리자 승격, 모델 실패의 오프라인 성공 치환, 원본 권한 확대, 검증 없는 지식/에이전트 효과 주장, 원격/기본 저장소의 기존 작업 덮어쓰기.

유예하는 것은 HPA·다중 앱 replica·DB HA·샤딩·전용 검색 클러스터·서비스 메시·대규모 처리량 최적화다. 인증·권한·백업·복구·감사·내구성은 유예하지 않는다. 동시접속 10명은 모델 호출 10개 무제한 동시 실행이나 HA 보장을 뜻하지 않는다.

## 3. 배포와 로컬 개발

- 운영: 기존 ADR 003대로 동일 클러스터 STG/PROD 별도 namespace, 앱 1개/DB 1개, 서로 다른 PVC·Secret·원본 저장·백업·서비스 계정. 단일 인스턴스 중단 가능성을 명시한다.
- 로컬: 전용 이름의 kind 클러스터에 앱·PostgreSQL·Keycloak을 배포한다. 기존 클러스터/context를 수정하거나 삭제하지 않는다. 삭제는 해당 작업이 만든 클러스터만 명시적으로 수행한다.
- 공통 Kustomize base와 local/stg/prod overlays를 사용한다. local만 합성 계정/개발 인증/loopback HTTP를 허용한다. 운영은 개발 비밀번호와 HTTP IdP를 거부한다.
- kind용 이미지를 로컬 빌드/load한다. 설치·기동·마이그레이션·준비 확인·검증·로그·종료를 재현 가능한 명령으로 제공한다. 빠른 수정은 로컬 앱 프로세스+kind DB/IdP 접속도 지원하되 최종 시험은 배포 이미지로 한다.
- DB는 앱과 별도 Pod, 원본/첨부는 별도 영속 blob adapter에 저장한다. local은 전용 PVC, 운영은 승인된 S3 호환 저장소 또는 검증된 영속 볼륨 adapter를 선택하도록 한다. blob 정본을 Pod 임시 디스크에 두지 않는다.
- 앱은 비루트·권한 축소·read-only root filesystem, probe·graceful shutdown·requests/limits를 갖춘다. 운영 이미지 digest 고정과 배포 전 단일 migration Job을 강제한다.
- NetworkPolicy는 기본 거부 후 DNS/Ingress/DB/IdP/허용 모델·저장소만 열고 CNI enforcement 여부를 시험한다. kind 기본 네트워크만으로 정책 집행을 검증했다고 주장하지 않는다.
- TLS 인증서·IngressClass·StorageClass·모델 egress·백업 외부 대상은 환경 입력이다. 실제 값이 없는 prod overlay는 fail-closed 검증을 통과하지 못해야 한다.

## 4. 인증·주체·권한

- 일반 OIDC Authorization Code + PKCE, state/nonce, discovery/JWKS 검증을 사용한다. 서버가 토큰을 보관하고 브라우저에는 HttpOnly/Secure/SameSite 세션 쿠키만 준다. 변경 요청은 CSRF/Origin 검증을 한다.
- 신원 키는 issuer+subject다. 이메일/표시 이름/요청 본문으로 신원을 결정하지 않는다. 허용 issuer/client/audience/그룹 매핑은 서버 설정이다.
- Keycloak fixture는 작성자·검토자·독자·비활성 사용자·분리 팀 계정을 갖춘다. 임의 외부 계정의 자동 가입을 허용하지 않는다. 로컬 관리자 bootstrap은 운영에 포함하지 않는다.
- 세션 만료·로그아웃·토큰 폐기·사용자 비활성화·그룹 변경을 검사하고, 권한 최신성을 확인할 수 없으면 보호 작업을 거부한다. 로그인 공급자 장애에서 무조건 기존 권한을 유지하지 않는다.
- workspace/개인/팀/전사 공간 membership, resource reader, owner/reviewer/operator를 구분한다. 원본과 파생 지식의 실효 권한은 교집합을 넘지 않는다.
- 모든 읽기·검색 결과/개수/제목·버전·답변 재열람·첨부·내보내기·MCP에 현재 권한을 적용한다. 정본 전체를 브라우저로 전달하지 않는다.
- 공유 확대는 권한 있는 사람이 명시적으로 검토한다. 철회·정정은 관련 페이지·답변·캐시·미결 승인·작업을 무효화/재검토한다. 이미 반출한 평문 회수는 보장하지 않는다.
- 에이전트는 개별 주체/제한 scope/만료/폐기 가능한 자격증명을 쓴다. 공통 관리자 키나 대화 속 사용자 이름을 신원으로 사용하지 않는다. 사내 SAML-only 환경은 후속 Keycloak broker 어댑터로 연결 가능하도록 경계를 둔다.

## 5. 정본·편집·검토

- 기존 DB 원자 발행/권한 스냅샷/멱등 영수증을 재사용한다. 원본, blob, 페이지/버전, 관계/주장/인용, 개인 draft/revision, changeset, 승인, Query/답변, Lint, outcome, job/outbox, 알림/감사/사용 기록은 서버 정본이다.
- 원본은 해시·버전·위치·수집 주체·자료 등급·시간·환경·검증 증거와 함께 등록한다. 편입으로 원본을 덮어쓰지 않는다. 정정은 새 버전/대체 관계, 철회·삭제는 별도 lifecycle이다.
- 개인 draft는 자동 공유하지 않는다. 저장/복구·버전 CAS·기기 충돌 보존·선택 revision 제안을 지원하고, 공유 제안은 동일 changeset 규칙을 통과한다.
- 작성/수정 → 검토 요청 → 승인/반려/수정 요청 → 발행의 상태를 분리한다. 수정 시 기존 승인을 무효화하고 새 해시로 재검토한다. 사람이 보호한 문단을 모델이 묵시적으로 교체하지 못한다.
- 기준/원본/내용/정책/ACL/의존 버전 변화 시 전체 발행 차단. 독립 변경만 별도 집합으로 분리 가능하며 의존 집합의 부분 발행은 금지한다. 복원은 새 버전이고 현재 ACL을 유지한다.
- 페이지 트리·속성·템플릿·내부 링크·문단 식별·diff·첨부·공식성/시행일·검토자/담당자·공유 만료·댓글/멘션/알림·즐겨찾기/최근 열람·검색 필터·생애주기를 기존 요구사항에 맞춰 서버 기능으로 옮긴다.
- 공개/게스트/익명 기능은 기본 비활성이고 운영 정책으로만 활성화한다. 비활성 경로의 서버 차단도 시험한다.

## 6. 지식 순환·모델·도구

- 서버가 권한 있는 원본과 관련 발행본을 선택하고 버전을 고정해 모델에 전달한다. 장시간 모델 호출 동안 DB 트랜잭션/잠금을 유지하지 않으며 결과 저장/발행 전에 다시 검사한다.
- provider adapter에서 base URL/model/key/timeout/출력·문맥 예산/전송 허용 정책을 설정한다. DeepSeek와 온프레미스 OpenAI 호환 API를 분리된 설정으로 검증한다. 사내 자료의 외부 전송은 기본 거부하고 개발 DeepSeek 시험에는 합성 자료만 사용한다.
- 비밀은 Kubernetes Secret/외부 비밀 저장소로 주입한다. 기존 외부 프로젝트 설정 파일은 실행 시 필요한 항목만 안전하게 읽으며 source로 실행하거나 전체 복사하지 않는다. 값은 검사 결과에도 출력하지 않는다.
- Ingest는 기존 결론·조건·관련 페이지를 재구성하는 다중 변경 제안이다. Query는 권한 있는 발행본의 정확한 인용/버전을 저장하고 부족하면 보류한다. 재편입은 파생 후보이며 독립 원본 증거로 계산하지 않는다.
- 주장별 원본 위치/계보·유효 시점/환경·추론/관찰/검증을 구분한다. Lint의 구조 검사와 확률적인 자연어 상충 제안을 따로 표시하고 자동 진실 판정/자동 공식 발행은 하지 않는다.
- 실제 토큰/공급자/모델/시간/실패를 계측한다. 비용은 공급자 가격 버전·실측 토큰이 있을 때만 산출하며 미수집은 null이다. 모델 호출 실패·429·시간초과·취소·출력 위반은 실패/재시도 상태로 남긴다.
- REST와 운영 MCP는 같은 서비스 계층을 사용한다. 검색/고정 버전 읽기/예산 내 업무 맥락/원본 등록/다중 변경 제안/성과 보고와 job 상태/취소를 지원한다. MCP가 승인·발행 권한을 임의로 얻지 않는다.
- 개인 커넥터의 기존 개발 프로토콜과 운영 도구는 버전을 명시한다. 선택 revision·source 검증·localCopyAllowed·공간 ID·충돌 보존을 유지한다. 첫 실제 수집기는 설치된 호스트의 배포 버전과 익명화 fixture로 검증하고, 추가 호스트는 별도 지원 상태를 표시한다.

## 7. 지속 작업·운영·안전

- PostgreSQL job/outbox에 수락·입력 버전·dedupe·lease/heartbeat·시도 횟수·backoff·취소·최종 상태를 저장한다. 한 앱의 처리기로 시작하되 분리 가능하게 한다. 강제 재시작·응답 소실·lease 만료에도 중복 발행하지 않는다.
- DB schedule/timezone와 실행 고유 키로 Daily/Weekly 작업을 생성한다. 동시 실행/사용자별 예산·대기열 상한·fairness·긴급 중지·수동 미리보기/재개를 지원한다. 무인 실행은 제안/점검까지이며 승인 정책을 우회하지 않는다.
- 파일 크기/유형·HTML 정제·민감정보·도구 실행 경계·SSRF/DNS/redirect/사설 주소 접근을 통제한다. 불필요한 원격 URL 수집/위험한 형식은 차단하고 지원 여부를 UI/API에 명시한다.
- 서버 감사와 사용 기록은 주체/trace/resource/action/result를 남기되 비밀·본문을 로그에 남기지 않는다. DB 감사와 별도로 운영자가 무단 변조하기 어려운 외부 감사 보관 adapter를 제공한다. 보관/삭제 정책과 운영자 접근을 설정한다.
- 백업은 DB와 blob의 일관성 있는 manifest/checksum·암호화·독립 보관을 포함한다. CronJob/수동 복구 명령과 폐기용 namespace 복원 시험을 제공한다. 같은 PVC 사본만으로 운영 백업을 선언하지 않는다. 삭제 tombstone을 복원 후 재적용한다.
- 초기 제안 목표(승인 전): DB/blob 일일 백업, 7개 일간 보관, RPO 24시간/RTO 4시간. 실제 조직 보존/삭제 정책이 더 엄격하면 우선하며 값이 미승인인 배포는 인수 미완료다.
- trace와 health/readiness·작업 대기/실패·DB/blob 용량·백업 나이·모델 오류/예산을 계측하고 알림 수신 adapter·운영 runbook을 제공한다. 실제 수신처/운영 담당자는 배포 입력이다.

## 8. 누락 방지와 구현 단위

아래는 순서 제안이며 특정 기능을 삭제하는 축소 범위가 아니다. 세부 계획은 설계 승인 뒤 작성한다. 하나의 거대 미검증 PR 대신 검증 가능한 누적 PR로 진행하고 요청된 머지는 각 PR의 회귀/CI 통과 후 수행한다. 이미 머지한 단위를 제외한 나머지는 작업표에 남긴다.

| 단위 | 범위 | 기존 기준 |
| --- | --- | --- |
| A | kind/Kustomize, 운영 앱 진입점, OIDC/세션/주체, DB 연결, 보안 기본값 | IAM, SEC, OPS, ADR003 |
| B | 공간/자료 ACL·철회, 정본 UI/API, 원본/blob, 검토·원자 발행·복원 | GOV, ACL, COL, VER, REV, CORE002~004 |
| C | 실제 모델 Ingest/Query/Lint/再편입, 주장 계보·시간/맥락·성과 | KNO, QNA, CORE001~008 |
| D | 운영 MCP/업무 맥락, 실제 도구 수집, 개인 작업본/충돌/공유 통합 | INT, COL, CORE009~010, KI01~07 |
| E | 편집/공유/댓글/알림/생애주기/사용량의 운영 UI·서버 | EDT, SHR, CLB, LIF, UX |
| F | 지속 작업/일정/예산/환류·감사·백업복원·관측·인수 | MGR, JOB, OPS, SEC, NFR, EVA, CORE011~012 |

239+12개의 모든 행을 요구사항 ID/수용 기준/현재 증거/담당 단위/구현 상태/검증 상태/외부 차단 요인에 연결한 작업표를 만든다. 필수 236개는 초기 운영 전 통과 대상이다. 확장 12개·선택 3개도 누락 없이 추적하고, 동시편집·SCIM·Webhook 등은 해당 기능의 명세와 활성화 시험을 별도 구현 단위로 이어간다. 확장 최적화 후순위 지시를 기능 요구사항 삭제로 해석하지 않는다. 선택 기능은 정책 승인 전 비활성 경로 차단이 수용 조건이다.

## 9. 검증과 출시 판정

- baseline: 지원 Node 24에서 기존 npm test, check:requirements, check:server, build와 DB 회귀를 확인한다. 실패 baseline은 사용자에게 보고하고 원인을 분리한다.
- 매 단위: 의미 있는 도메인/HTTP/DB 회귀, 위험 경로 RED→GREEN, 독립 리뷰, npm test/check:requirements/build, 관련 서버 및 배포 시험을 수행한다.
- kind E2E: 실제 Keycloak 브라우저 로그인부터 두 사용자 등록/검토/발행/검색/질문/재편입/점검, 거부/철회/세션 만료/재시작/모델 실패/복원/백업을 확인한다.
- 390px/1440px 실제 브라우저에서 한국어 UI·키보드·초점·내부 표 스크롤·SVG 표시 글자·첫 결론 위치·문서 길이를 검증한다. 대량 목록은 검색/페이지 분할하고 원본을 보존한다.
- 10개 인증 세션의 읽기/검색/제안/발행과 제한된 모델 작업을 혼합해 재현 가능한 데이터 규모/예산/동시성/지연/오류를 기록한다. 초기 제안 SLO는 모델 제외 읽기/검색 p95 1초 이하, 안전 위반 0건이며 실제 측정 전 보장하지 않는다. 모델 지연은 별도 측정한다.
- 기존 35개 인수 시험, CORE 및 KI/KE를 실행/실패/미실행으로 분리한다. 평가 runner/합성 fixture는 실제 모델 의미/후속 에이전트 성능 개선의 독립 증거가 아니다. 사전 기준/정답/표본·독립 검토가 없으면 효과 판정을 보류한다.
- PR별 docs/AGENT_HANDOFF.md에 ID·변경·명령/실제 결과·한계·다음 작업을 갱신한다. 외부 차단 요인이 있으면 전체 완료로 보고하지 않는다. CI/보호 규칙을 우회해 머지하지 않는다.

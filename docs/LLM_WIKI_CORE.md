# LLM Wiki 핵심과 현재 구현

기준일: 2026-10-27. 이 문서는 제품 방향과 코드의 관계를 정의한다. 기능·보안·운영 요구사항을 축소하지 않는다.

## 원전과 이 서비스의 선택

출처는 Andrej Karpathy의 [LLM Wiki 원문](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f)이다. 핵심은 원본을 매 질문마다 다시 조립하는 대신, LLM이 연결된 위키를 지속적으로 작성·유지하고 새로운 자료와 질문의 결과를 누적하는 패턴이다. 원본·위키·유지 규칙을 구분하며 Ingest·Query·Lint를 수행한다. 사람은 자료 선택·질문·탐색에 관여한다. 에이전트만 읽는 형식이나 MCP 자체가 핵심이라는 해석은 피한다. 원전은 개념 안내이며 특정 서버·DB·인증 제품을 요구하지 않는다.

Folio의 추가 선택은 LLM 업무 산출물을 주요 입력으로 삼고 개인·팀·전사 범위를 갖추며 승인·발행·감사·운영을 적용하는 것이다. 에이전트가 지식 작성과 유지관리를 수행하면서 사람도 읽고 검토할 수 있어야 한다. Markdown과 구조화된 근거·조건·버전을 함께 제공한다.

## 실제 동작

| 순환 | 코드 | 현재 범위 |
| --- | --- | --- |
| 원본 보존 | domain/wiki.ts의 createBatch | 원본 스냅샷 고정, 발행 전 재검사 |
| Ingest | compileOffline / adapters/model.ts의 compileModel | 주제·개념·연결을 하나의 변경 집합으로 제안 |
| 검토·발행 | enqueueBatch / decideBatch | 승인 내용 고정, 원본·기준 버전 충돌 시 전체 차단, 중복 발행 방지 |
| Query | retrieve / answerOffline / answerModel | 현재 발행본 검색, 정확한 인용 검사, 고정 버전 조회 |
| 질문 결과 축적 | fileAnswer | 파생 페이지의 변경 집합 생성, 근거 부족·오래된 인용 거부 |
| Lint | lintWiki / runLint | 실제 깨진 연결·고립·근거 누락·검증 시점·동일 조건 사실 충돌 검사 |
| 인덱스·로그 | KnowledgeWorkbench / State.audit | 현재 발행본과 관계 탐색, 편입·질문·점검 기록 |
| 규칙 | wiki/SCHEMA.md | 유지관리 에이전트 규칙, 실제 모델 system 메시지에 포함 |

## 두 실행 모드의 차이

오프라인 모드는 `## 지식: 제목`으로 개념을 추출하고 `사실: key | context | value`를 명시 사실로 읽는 작은 입력 언어다. 기존 주제의 관련 지식 목록과 개념별 원본 기록을 갱신한다. 일반 산문은 별도 사례 페이지로 분류한다. 자연어 의미를 종합한 것처럼 설명하지 않는다. 질문 결과는 검색된 발행본의 정확한 발췌다.

모델 모드는 .env에 설정한 OpenAI 호환 서버에 원본과 기존 발행본을 보내 실제 종합·답변 요청을 수행한다. schema 검사·근거 인용·공유 범위·발행 규칙은 모델의 판단에 맡기지 않는다. 실패하면 오류를 표시하고 반영하지 않는다. 실제 사내 모델의 품질과 호환성은 별도 검증해야 한다. 자연어 전반의 의미 모순 검사 모델 연동은 아직 없다.

## 저장과 상태

기존 schemaVersion 1 데이터와 호환되며 추가 상태는 State.knowledge에 저장한다. 이전 데모 데이터가 있으면 빈 knowledge 상태에서 시작한다. 브라우저 localStorage이며 다중 탭의 동시 편집·서버 권한·DB 트랜잭션을 보장하지 않는다. 일괄 발행은 단일 로컬 상태 전이로만 원자적이다. 원본 정정·삭제·권한 철회·전체 백업은 운영 구현에서 추가한다.

현재 버전 본문은 보존하지만 페이지 관계·사실 메타데이터의 과거 전체 복원과 별도 검증 승인 상태 전이는 후속 구현이다. 최신 수정일을 검증일로 간주하지 않는다. 초기 데이터에 근거 누락·검증일 누락이 있어 Lint에서 보이는 것은 의도한 점검 결과다.

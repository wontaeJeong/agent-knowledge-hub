# 에이전트 중심 운영 콘솔 · UI 목업

2026-10-30. 최신 `main@31b7d9a`의 자료 편입·Organization/Team/공간 접근 관리를 보존하고 운영 개요와 독립 목업을 추가했다. **251개 제품 수용 기준 전체의 구현·운영 인수 완료가 아니다.**

## 열어보기

```bash
npm ci
npm run build
npm run preview
```

- `/?preview=1`: 서버·로그인 없이 보는 합성 UI 목업. `#overview`, `#users`, `#agents`, `#access` 등 화면 직접 링크를 지원한다.
- `/?app=1`: 실제 서버 UI. 기본은 운영 개요이고 기존 지식·편입·검토·질문·Lint·사용량과 최신 자료 입력/공간 접근 관리를 그대로 제공한다.
- `/`: 기존 소개. `/?demo=1`: 기존 브라우저 데모. 두 경로는 그대로 유지한다.

목업은 예시 데이터와 메모리만 사용한다. 실제 API·SSO·파일 업로드·모델을 호출하지 않으며 새로고침하면 초기화된다. 서버 오류 뒤에 목업으로 자동 전환하지 않는다. 실제 개인정보·업무 자료·키를 입력하지 않는다. 예시 토큰도 실제 비밀 원문을 생성하지 않는다.

## 지표 해석

- 목록 개수는 **현재 접근 범위의 개체 수**, jobs는 **본인 시도 이력**이다. 팀 전체 건강도/전환율/검토 지연을 추정하지 않는다.
- 계측 대상은 `page.read`, `source.register`, `batch.propose`, `batch.approve`, `batch.publish`다. 질문·Lint·목록 조회 등 전체 API 사용량이 아니다. 목록 본문을 브라우저에서 펼친 행동도 별도 조회 이벤트가 아니다.
- 성공/실패는 호출 기준이고 재시도도 포함한다. 실제 발행 건수와 다르며, 성공 호출이 지식 정확성/후속 업무 성공을 뜻하지 않는다.
- 활성 사용자는 기간 내 기록된 호출 주체 고유 수다. 로그인/조직 멤버/생산성 순위가 아니다. 현행 실제 집계 범위는 관리 이관 공간 Admin 또는 미이관 공간 reviewer의 공간 집계/그 외 본인 집계를 서버가 결정한다.
- 분모 0은 실패율 `해당 없음`, 모델 토큰/비용은 `미수집`, 지식 효과는 `미평가`다. 평균 시간은 실패 포함 평균이며 p95나 성공 지연으로 바꾸어 부르지 않는다.
- 페이지/원본 목록 조회 실패 시 개요의 수치 카드를 표시하지 않는다. 탭을 떠난 뒤 늦게 도착한 401도 보호 상태를 제거한다. 이전 세션의 늦은 목록 응답은 새 상태에 반영하지 않는다.

## 안전·평가와 남은 조건

목업에서도 마지막 Owner 제거, 미수락 초대의 계정 활성화 우회, 서비스 토큰의 승인/발행 위임, 개인 공간 공개 확대, 원본 반출 금지를 차단한다. 이 규칙은 **합성 시나리오의 일관성**이지 운영 서버의 인증/권한 구현을 대신하지 않는다. 실제 정책 계약은 [접근 제어](ACCESS_CONTROL.md)와 [최신 구현 범위](IMPLEMENTATION_GUIDE.md)를 따른다.

North Star의 Ingest→Query→Lint·결과 재편입을 운영 관점에서 드러내고 근거/현재 권한/검토 불변식을 유지한다. 지식 본문/기존 발행 엔진·런타임 규칙의 의미는 바꾸지 않는다. 범위 토큰·서비스 주체·예약 유지관리·전역 계정/세션·문서 공유/수명주기·알림 등 남은 운영 연결은 후속 구현이다. 지식 품질·후속 에이전트 성능은 [평가 계약](EVALUATION.md)의 대조 실험 전까지 미평가다.

검증·실제 화면·동일 fixture의 전후 비교는 [캡처와 검증 기록](pr-assets/agent-console/README.md)을 참고한다.
